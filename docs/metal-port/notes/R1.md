## What was ported (all in `risc0/circuit/rv32im-sys/kernels/metal/`)

| File | Ported from | Notes |
|---|---|---|
| `cuda_compat.h` | (new; on top of build_kernel `cuda2metal.h`) | `std::initializer_list` stand-in (witgen_tu.cu/steps.cu pass `std::initializer_list<Val>{..}` to the no-op `extern_log`; MSL has none), `rv32im_index_t`/`rv32im_cell` (32-bit column-major indexing, `RV32IM_WIDE_INDEX` for 64-bit), `RV32IM_FAULT_*` bits, `RV32IM_ASSERT_SIZE/OFFSET` (`offsetof` is not a macro in MSL; `__builtin_offsetof` works). |
| `preflight.h` | cuda/preflight.h, intel/preflight.h | `MemoryTransaction` (20 B) / `PreflightCycle` (36 B) with size + every field offset static_asserted. `PreflightTrace` becomes a thread-local struct of `device` pointers (+ lengths for clamping), built by kernels from explicit bindings. |
| `buffers.h` | cuda/buffers.h, intel/buffers.h | `Buffer { device Fp* buf; uint rows, cols; }` (FFI-only `checked` dropped). `RV32IM_ORDERED_ROWS` = volatile 32-bit accesses (the closest MSL analogue of the HIP `asm volatile` barriers); off by default (plan: pre_data buffer). |
| `tables.h` | cuda/tables.h, intel/tables.h (atomic_ref precedent) | relaxed `atomic_fetch_add` on `device atomic_uint*`; bad table/index sets `bad` bits and touches nothing (CUDA asserts, a no-op, then indexes OOB). `count` ignored as on CUDA/CPU. |
| `ef_fp.h` | cuda/ef_fp.h device paths (EF_FP_FAST), `inv_chain` from cuda/witgen.h:224 | **Free functions over fp.h's `Fp`** (plan 2.2: no second Fp class): `ef_mulhi` (32-bit `metal::mulhi`), `ef_mulM`, `ef_add/sub/mul/neg(_raw)`, `ef_redc_lohi`, `inv_chain`. Translation rule for R12: `Fp::mulM(x)` → `ef_mulM(x)`. |
| `ef_fpext.h` | cuda/ef_fpext.h EF_EXT_LAZY (RISC0_INTEL_EVAL_LOHI redc4 form), `inv_ext_chain` from cuda/witgen.h | `ef_redc4` (32-bit lo/hi carries; `EF_WIDE` → `ulong` accumulate), `ef_ext_mul` (lazy FpExt multiply), `inv_ext_chain`. Generated code calls `ef_ext_mul` where CUDA's EF_EXT_LAZY changed `operator*`. |
| `witgen.h` | cuda/witgen.h (non-virtual branch), intel/witgen.h | One kind-tagged `BufferObj` (no inheritance/virtual) built by `makeMutableBuf(buf[, pre, zeroBack])` / `makeGlobalBuf(buf)`; `MutableBuf`/`GlobalBuf` = `thread BufferObj*`. `BoundLayout<T>` holds `const constant T&`; no CTAD in MSL 3.2 (C++14), so `BIND_LAYOUT`/`LAYOUT_LOOKUP`/`LAYOUT_SUBSCRIPT` expand to `bindLayout(...)`. `ExecContext.cycle` is `uint32_t`; `Reg.col` is `uint32_t` with a `constant` constructor. map/reduce kept with functors. Extern declarations with `thread ExecContext&` and `constant char*` strings. Generated `.metal.inc` included only under `RV32IM_METAL_INCLUDE_GENERATED` (R3 produces them). |
| `seq_exec.h` | ffi.cu:710-724 (`fwd_stepExec`/`rev_stepExec`) | Chunked drivers `rv32im_seq_fwd/rev(step, SeqParams)`: positions [begin,end) of CUDA's order, `RV32IM_SEQ_CHUNK = 4096`; host encodes one 1x1 dispatch per chunk in one encoder. |
| `misc.metal` | ffi.cu:674 `injectCycleCols`, ffi.cu:1190 `finalizeZeroizeAccum` | 1:1 ports with explicit bindings + POD params (`InjectParams` 32 B, `FinalizeAccumParams` 16 B, `SeqParams`/`SeqProbeParams` 16 B, static_asserted). `finalizeZeroizeAccum` takes `userAccumSplit` as a param (CUDA: compile-time `kLayout_TopAccum.columns[0].col` = 23) so it does not depend on the generated layout; malformed params only zeroize (CUDA's size_t would wrap). Also `seq_fwd_probe`/`seq_rev_probe`: the seq_exec.h drivers instantiated with an order-sensitive probe step. |
| `r1_check/` | (new; D0 runner precedent) | Standalone crate (`metal 0.29`, `objc 0.2`, empty `[workspace]`, Cargo.lock copied from D0's runner) running the Metal-vs-CPU checks below; `selftest.metal` exercises the headers. |

## Assumed / not verified
- The headers are exercised by the selftest, not by translated zirgen code (R2/R3/R5 have not landed). Layouts are assumed to be `constant constexpr` (R3 must emit them that way for `BoundLayout`'s `const constant T&`).
- No GPU-vs-CPU test through `risc0_zkp::hal::metal::MetalHal`: rv32im-sys has no dev-dependency on risc0-zkp or metal, and its Cargo.toml is not R1's. The standalone runner is the fallback the item allows; R7/R8 should add HAL-level tests.
- `RV32IM_ORDERED_ROWS` (volatile accesses) compiles but has no test that it prevents the back-row reordering race; that is R15's single-buffer experiment.
- The 32-bit indexing relies on the host asserting rows × cols < 2^32 (R7/R8/R9).

## Deviations / known gaps
- `build_metal_kernels` also got `.include("kernels/metal")` (beyond swapping the file list): without it the headers are not in the metallib cache key, so editing one would not rebuild. Side effect: files under `kernels/metal/r1_check/` (not `target/`, which `kernel_source_files` skips) are part of the key too.
- `fwd_stepExec`/`rev_stepExec` themselves cannot be defined in misc.metal yet (they need the generated `step_Top`; an undefined extern fails the metallib link, D0). seq_exec.h provides the chunked drivers; R5 defines the two kernels in witgen_tu.metal with them. The probe kernels stay in the metallib for tests (R8 may drop them).
- witgen.h API differences from CUDA a translator must apply: `MutableBufObj x(...)` → `BufferObj x = makeMutableBuf(...)`; `BoundLayout(a, b)` → `bindLayout(a, b)`; `Fp::mulM` → `ef_mulM`; EF_EXT_LAZY `a * b` → `ef_ext_mul(a, b)`; `ExecContext&` → `thread ExecContext&`; string params `constant char*`.
- Rust `#[repr(C)]` mirrors of the misc.metal params live only in the runner; R7 owns the HAL-side mirrors.
