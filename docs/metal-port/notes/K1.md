# K1: keccak Metal build plumbing + HAL skeleton

Branch `metal/K1` (worktree `/Users/user/zkminer/deps/risc0-wt-K1`), based on `zkminer/metal` `93978a8e8`.
Plan: PLAN.md 4.4 row K1, errata 8.2 / 8.4.

## What was done
- `circuit/keccak-sys/kernels/metal/scatter.metal` (new): `scatter_preflight`, a 1:1 port of
  `kernels/cuda/ffi.cu:161-181` (one thread per `ScatterInfo`; same loop, `into[col * rows + row] = Fp(val)`).
  `ScatterInfo` (ffi.cu:41-47) is mirrored and `static_assert(sizeof == 16)`. Additions per plan 2.4/2.9:
  `[[max_total_threads_per_threadgroup(256)]]` before `kernel`, a `ScatterParams {rows, cols, count, from_len}`
  (16 B, `set_bytes`), and a `device atomic_uint* fault`: an info with `bits` outside 1..31, `row >= rows`,
  `col + count > cols`, or a last source word past `from_len` is skipped and ORs the flag (CUDA has no
  checks; the CPU path `assert!`s). Bindings are documented at the top of the file and mirrored as
  `SCATTER_*` constants in Rust.
- `kernels/metal/noop.metal` deleted; `METAL_KERNEL_NAMES = &["scatter_preflight"]` (keccak-sys `src/lib.rs`).
- keccak-sys `src/lib.rs`: compile-time asserts on `ScatterInfo` (size 16, align 4, field offsets 0/4/8/10/12).
- keccak-sys `build.rs`:
  - `#[path = "build_metal_eval.rs"] mod build_metal_eval;` (the one line for K3).
  - `build_metal_kernels()` now globs `kernels/metal/*.metal` (sorted), appends
    `build_metal_eval::metal_eval_sources(kernel_dir, $OUT_DIR/metal)` (skipped under `RISC0_SKIP_BUILD_KERNELS`),
    puts `kernels/metal` on the include path (so it is hashed into the metallib cache key) and passes
    `-std=metal3.2 -O2` explicitly; `rerun-if-changed` on `kernels/metal`. `KECCAK_METAL_PATH` as before.
- `keccak-sys/build_metal_eval.rs` (stub, K3 owns it from now on): module doc plus a hook
  `metal_eval_sources(kernel_dir, gen_dir) -> Vec<PathBuf>` returning nothing. **Deviation**: the task said
  "empty stub with a comment"; a truly empty module would force K3 to edit build.rs to call its translator,
  which 8.2 forbids, so the stub carries the call site's hook with an empty body.
- `keccak/src/prove/hal/metal.rs` moved to `hal/metal/mod.rs` (`hal/mod.rs`'s `pub(crate) mod metal;` line is
  unchanged and still correct). Contents:
  - `MetalCircuitHal<MH> { hal: Rc<MetalHal<MH>>, kernels: MetalKernels }` (`Rc` as cuda.rs).
    `new` loads `METAL_LIB` with a PSO for every `METAL_KERNEL_NAMES` entry (F0's `load_library`, panics on a
    missing name); `pipeline(name)` is the PSO map lookup.
  - `scatter_preflight_gpu(into, infos, from) -> Result<()>`: copies infos/from into pooled shared buffers,
    dispatches `scatter_preflight` (`Grid::Threads(count)`), `try_sync`, reads the fault flag and `bail!`s.
    Not yet called by the prover (K2 switches `scatter_preflight` to it); used by the tests.
  - `CircuitWitnessGenerator`: `type PreferredPreflightOrder = ForwardPreflightOrder`, `HOST_WITNESS = true`;
    `scatter_preflight` and `generate_witness` run `scatter_preflight_host` / `generate_witness_host` (cpu.rs)
    over `view_mut` of the shared buffers.
  - `CircuitHal`: `accumulate` no-op (as cuda.rs); `eval_check` = the `CpuCircuitHal::eval_check` loop
    (`risc0_circuit_keccak_cpu_poly_fp` per cycle, rayon) over `view`/`view_mut` of the Metal buffers
    (duplicated, because cpu.rs is not K1's file); `eval_check_dep` explicit no-op (one queue, plan 2.0).
  - **Drop: not needed.** CUDA's `Drop` calls `cuda_reset` to undo the stack-size limit its witgen raised;
    Metal has no such process-wide state. PSOs and the HAL `Rc` drop normally; buffers go back to the HAL pool
    after their last batch (F0).
  - `keccak_prover()` returns `KeccakProverImpl<MetalHalPoseidon2, MetalCircuitHalPoseidon2>` and logs
    `keccak: Metal prover on <device>` at debug level.
- `prove/mod.rs`: the F2 metal arm (`else if #[cfg(feature = "metal")]` with `enabled("keccak")`, CPU fallback)
  already matched the plan; no change was needed. `prove/tests.rs` untouched (its `fwd_rev_ab` metal branch is K2's).

## Tests added (in `hal/metal/mod.rs`)
- `metal_scatter_matches_host`: po2 8 and 12, preflight from `test_inputs`, GPU scatter into an INVALID-filled
  `MetaBuffer` vs `scatter_preflight_host` into an INVALID `Vec`: 0 differing cells, and some cells written.
- `metal_scatter_rejects_bad_info`: a valid hand-made info writes the expected values; six invalid infos (column
  past cols, row past rows, first/last word past `from`, bits 0, bits 32) each return `Err("... invalid ScatterInfo")`
  and leave the buffer untouched.
- `metal_prover_runs_on_metal_hal`: proves the HAL type. A `cfg(test)` thread-local counter is incremented by
  the Metal circuit HAL's `eval_check`; `crate::prove::keccak_prover()` (the factory `basic` uses) proves po2 8,
  the counter goes up by exactly one, and the seal verifies; the same through `prove_host_witness`. Skips when
  `enabled("keccak")` is false.

## Assumed / not verified / gaps
- The scatter kernel's fault checks are stricter than CPU's (`col + count > cols` is rejected even when the
  index would still land inside the buffer in a later column); every preflight info satisfies them (the po2 8/12
  equivalence test shows no fault).
- No timing recorded: scatter is not on the prover path yet (K2), and the GPU was shared with other agents.
- `rows * cols` must fit u32 (asserted on the host); true up to po2 18 for keccak's `REGCOUNT_DATA`.
- `host_witness`/`fwd_rev_ab` currently run with CPU witgen over shared buffers; `fwd_rev_ab` still uses the
  CPU HAL branch under `--features metal` (K2 adds the metal branch).
- K6's `build_metal_witgen.rs` (8.2) will need its own `mod` line in build.rs; K1 did not add it (not in scope).
