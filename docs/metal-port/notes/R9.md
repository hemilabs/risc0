### Accum sequence (`step_accum_metal`)
0. `ctx.require(Phase::Accum)`. Host checks:
   - data and accum rows are powers of two (CUDA throws otherwise);
   - `n = cycles ≤ rows`;
   - `accum.cols ≥ split + 4`;
   - each buffer holds `rows × cols` elements;
   - `rows × cols` fits in a u32 (R1's 32-bit indexing).
1. **perm (CPU)**: `build_perm` runs one counting sort per 2^win-row window (rayon over windows). It writes into the reused `scratch.perm` after a `try_sync`. The result equals the CUDA stable radix sort of `majorKeys` keys `(i >> win) << 8 | major`.
   - `RISC0_METAL_ACCUM_SORT`: `0` or `off` means no perm (`hasPerm = 0`, accum bound at index 4); `4..=24` sets the window. The default is **14**, as in CUDA `s_win`.
   - n ≤ 1 skips the perm.
2. **Batch [blit_fill fault word = 0, stepAccumA]**, then `try_sync`. A nonzero fault word is an error (`bail!`) that names the bits: 0x10 for a circuit assert, 0x20 for an out-of-range perm entry.
3. **CPU scans**: an inclusive Fp prefix sum over the first `n` rows of each of the last 4 accum columns, using raw-word `fp.h` addition, so the result is bit-identical even on INVALID words. The 4 columns run in parallel.
4. **Batch [finalizeZeroizeAccum(rows, cols, lastCycle = n, split = LAYOUT_TOP_ACCUM.columns[0] = 23)]**, then `try_sync`. This closes the phase and attributes any command-buffer error to accum. With n = 0 only this step runs, and it only zeroizes.

`step_accum_zeroizes()` is true on the GPU path, as on CUDA. Under the CPU fallback it is false, and the prover zeroizes.

`CircuitHal::accumulate` is still the empty no-op that `hal/cuda.rs` has (PLAN 8.4). It lives in `eval_check.rs` (R10's file), and I checked it without editing it.

**CPU fallback**: `RISC0_METAL_RV32IM_CPU_PHASES=…,accum,…` (comma list, case-insensitive, read once) selects `step_accum_cpu`. The helper `names_phase` and the constant `CPU_PHASES_ENV` are `pub(crate)` in `accum.rs`; R8/R10 can reuse them or keep their own.

Tests in `prove::hal::metal::accum::tests`:
- **`accum_matches_cpu`**. Programs: kernel `basic` (po2 13), `multi_read` (po2 14), `simple_loop(60000)` at po2 16, and riscv-tests `rem mul divu sb lhu` (po2 13).

  - On Metal, witgen runs on the current Metal path. Its data/global are then overwritten with the CPU witness, so that accum is isolated from R8. A mismatch is logged as a warning and was never seen.
  - Accum then runs in 4 variants: GPU win 14, GPU win 11, GPU no perm, and the CPU fallback.
  - **All 103 accum columns** (user, finalized machine and scanned) are compared bit-for-bit. A failure reports `first_diff`: row, column, column kind, CPU vs Metal word, and the diff count. The test also asserts that no INVALID word is left.
- **`perm_equivalence`**: `build_perm` equals a stable sort of CUDA's keys for:
  - n ∈ {1, 2, 5, 255, 2047, 2048, 2049, 2^14+3, 100000}, windows {4, 11, 12, 13, 14, 24}, with random majors (all 256 values, and 19 values);
  - constant majors (gives the identity);
  - the majors of a real po2 15 trace, windows 11..14.
  
  It also checks that nothing is written past n.
- **`fp_scan_matches_field`**: the raw scan equals `Val` addition for sizes 1, 255, 256 and 2^20+7, and the empty case works.
- **`bad_perm_faults`**: a perm with entries ≥ count sets fault bit 0x20 (no out-of-bounds read).
- **`sort_window_env_values`**: env parsing, and `user_accum_split() == 23`.
- **`accum_measure`** (ignored) and **`prove_segment_measure`** (ignored): the measurements below.

- **Speedup over the R7 CPU delegation:** about 40× at po2 20 (19 ms vs ~800 ms).
- **CPU share at po2 20:** the CPU-side stages are small (perm ~1 ms, scans ~2 ms). Each phase still has three host waits; R13 (GPU scans) removes the middle one.
- **Cold PSO:** the first `accum_matches_cpu` run in this worktree spent ~250 s before the first case. That covers the cold PSO creation for this worktree's metallib build (stepAccumA ~40-95 s per R4) plus the zkp PSOs. Later runs took seconds. This is the R4/M1 warm-up issue; R9 adds nothing to it.

## Assumed / gaps
- **No bigint programs in the accum tests.** No provable bigint test program is reachable from the rv32im crate (kernel `poseidon2` is rejected by the 3.0 circuit, so I dropped it). The bigint accum injection runs on the host either way, but `stepAccumA`'s bigint-major arms are not covered by `accum_matches_cpu`. R11's 46 riscv cases / zkvm e2e cover more majors.
- **Interleaving with GPU witgen not exercised.** The accum comparison replaces Metal witgen output with the CPU witness, so it does not test R8's GPU witgen together with GPU accum. R11 does that.
- **Host waits.** The phase does `try_sync` three times (before writing perm, after stepAccumA, after finalize). The last one could be a `flush` (R14).

## Issues for later items
- **R13**: GPU scans replace step 3 and merge steps 2-4 into one command buffer. `fp_inclusive_scan` and `accum_matches_cpu` are the oracles.
- **R14/R15**: sweep the window on an idle GPU and on 8-10-core parts. Consider dropping the end-of-phase wait.
- **Z6/F0 owner**: a budget overrun in `BufferImpl::new` panics, so `prove()` cannot return it as an error. The worker needs either `catch_unwind` or a fallible allocation path. po2 20 rv32im needs about 9.2 GB of GPU memory, so it fits neither the 4 GB nor the 8 GB minimum-tier budget (PLAN 9.1 expects po2 ≤ 18/19 there, which matches).
- **R11**: add a bigint guest to the accum/prove conformance tests.
