# F2: feature and build wiring for the Metal port

Branch `metal/F2`, based on `zkminer/metal` (`c2e2db13d`).

## What was done

Follows PLAN.md 2.0 (backend selection, runtime escape hatch, metallib location), 2.8 (names, cargo
variables, build gating), section 3 row F2, and errata 8.1/8.2.

- **Cargo features** (8.1, as written except where noted below):
  - `risc0-zkvm`: `metal = ["prove", "risc0-circuit-{keccak,recursion,rv32im}/metal", "risc0-groth16/metal", "risc0-zkp/metal"]`.
  - `risc0-zkp`: `metal = ["prove", "dep:metal", "risc0-sys/metal"]`; the macOS/iOS `metal` crate dependency is now `optional = true`.
  - `risc0-circuit-rv32im`, `risc0-circuit-keccak`: new optional target-gated `metal` dependency; `metal = ["prove", "dep:metal", "risc0-circuit-<x>-sys/metal", "risc0-zkp/metal"]`.
  - `risc0-circuit-recursion`: `metal = ["prove", "dep:metal", "risc0-circuit-recursion-sys/metal", "risc0-zkp/metal", "std"]`; its `metal` dependency is now optional.
  - `rv32im-sys`, `recursion-sys`, `keccak-sys` (new feature): `metal = ["risc0-sys/metal"]`.
  - `risc0-groth16-sys`: `metal = ["dep:risc0-sys", "risc0-sys/metal", "dep:metal"]` plus an optional target-gated `metal` dependency.
  - `risc0-groth16`: `metal` copies the `intel` list: `dep:circom-witnesscalc`, `dep:rayon`, `dep:risc0-groth16-sys`, `dep:sha2`, `dep:wtns-file`, `prove`, `risc0-groth16-sys/metal`, `risc0-zkp/metal`.
  - `risc0-sys` keeps `metal = []`.
- **Build gating**: `sys/build.rs` builds `metal_kernels_zkp` only when `CARGO_FEATURE_METAL` is set and the target OS is macOS or iOS. It used to build it on every macOS build. `zkp/build.rs` uses the same condition to emit `ZKP_METAL_PATH`; it used to use `prove`. `zkp/src/hal/mod.rs`: `#[cfg(all(feature = "metal", any(target_os = "macos", target_os = "ios")))] pub mod metal;` (it used to be gated on the target alone).
- **Guards** (`compile_error!`):
  - `metal` with `cuda|rocm|intel`: in the build scripts of `risc0-sys`, all four `-sys` crates and `risc0-zkp` (the build script errors before any GPU toolchain is run); in the `src/lib.rs` of `risc0-sys` and all four `-sys` crates; and in `risc0-zkvm/src/lib.rs`.
  - `metal` on a target other than macOS/iOS: in `zkp/src/hal/mod.rs`, in `risc0-sys` and every `-sys` `src/lib.rs`, and in `risc0-zkvm/src/lib.rs`. `sys/build.rs` also panics with the same message, so the error shows up before dependencies that fail to cross-compile.
- **`-sys` skeletons**: each of rv32im-sys, recursion-sys, keccak-sys and groth16-sys has a `build_metal_kernels()` (gated by `metal_enabled()`, which applies the same feature and target condition). It compiles `kernels/metal/noop.metal` with `KernelBuild::new(KernelType::Metal)`; the `KernelBuild` API is unchanged. The output is `metal_kernels_<unit>`, and the build script prints `cargo:rustc-env=<UNIT>_METAL_PATH=<OUT_DIR>/metal_kernels_<unit>.metallib`. Under `RISC0_SKIP_BUILD_KERNELS` it points at the empty `skip-` file instead. Each `src/lib.rs` has `METAL_LIB` (`include_bytes!`) and `METAL_KERNEL_NAMES = &["noop"]`, both gated on the feature and target. Per 8.2, the unit's first kernel item deletes `noop.metal` and its entry in the names list.
- **zkp runtime helpers** (`zkp/src/hal/metal.rs`; nothing else in that file changed):
  - `pub fn enabled(unit) -> bool` returns false when `RISC0_METAL=0`, or when the comma list in `RISC0_METAL_SKIP` names the unit (trimmed, case-insensitive).
  - `pub fn device_name() -> Option<String>` returns `Device::system_default()` name.
- **Circuit stubs**: `rv32im`, `keccak` and `recursion` have `hal/metal.rs` with `#[cfg(feature = "metal")] pub(crate) mod metal;`. Each factory (`segment_prover`, `keccak_prover`, `recursion_prover(hashfn)`) returns the CPU prover. Each `prove/mod.rs` has an `else if #[cfg(feature = "metal")]` arm after `intel` and before the CPU fallback: it calls `risc0_zkp::hal::metal::enabled("<unit>")` and falls back to CPU. The commented-out legacy metal arms were removed.
- **recursion cleanup**: deleted the stale `recursion-sys/kernels/metal/{eval_check,step_compute_accum,step_verify_accum}.metal`. The stale `recursion/src/prove/hal/metal.rs` (pre-#3114 `CircuitHal`, `RECURSION_METAL_PATH` with no producer) is replaced by the stub.
- **groth16**:
  - New `src/prove/metal.rs` stub. It has `const AVAILABLE: bool = false`, and `enabled()` = `AVAILABLE && risc0_zkp::hal::metal::enabled("groth16") && RISC0_GROTH16_METAL_PROVER != "docker"`. It also has stub entry points: `preload_graph` delegates to `fast::preload`, `prestart*`/`preload_srs`/`release_srs`/`invalidate_caches` are no-ops, `shrink_wrap` bails, and `witness` is kept for G1.
  - Every cfg site listed in 8.1 has a metal arm: `mod component`, `mod fast`, a new `mod metal`, `preload_graph`, `preload_graph_background`, `prestart_prover`, `prestart_key`, `prestart_key_go`, `preload_srs`, `release_srs`, `invalidate_caches`, `shrink_wrap_with`, `shrink_wrap`, and both `docker.rs` `fast_enabled` sites. `mod docker` already compiled for metal (`not(any(cuda, rocm))`). With `AVAILABLE = false`, every arm takes the Docker/no-op path. G1/G7 change only `metal.rs` and set `AVAILABLE` to true.
- **zkvm**: kept `metal_implies_prove`; updated the `metal` row of the crate feature table.

## Deviations / decisions

- groth16 `metal` also lists `dep:sha2`. It is in the `intel` list that 8.1 says to copy, and `fast.rs` (compiled for metal) needs it.
- On metal builds the groth16 fast Docker path (`docker.rs::fast_enabled`) is opt-in (`RISC0_GROTH16_FAST=1`) rather than on by default as for intel. Its named pipe through the Docker VM's file sharing on macOS has never been run, so the default stays the plain Docker prover.
- The mutual-exclusion guard was also added to `zkp/build.rs` (an owned file), so that it fires as early as possible.

## Assumed / not verified

- No test covers `enabled()`/`device_name()` (F0 owns the test module). The logic is straightforward, but the env-variable behaviour was not exercised.
- `METAL_LIB` was not loaded at run time with `new_library_with_data`. Only the build and the `include_bytes!` were checked.
- Not checked on an iOS target.
