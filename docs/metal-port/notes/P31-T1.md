## 2. Tooling changes on top of W7-T1

- `emit_ir.sh`:
  - **Bug fix.** `newest()` returned the exit status of its `while read` loop. When the newest
    `OUT_DIR` of a crate had no `metal/` subdirectory, the status was 1, and `RV=$(newest ...)` killed
    the script silently under `set -e` (rc 1, no message). That is the silent failure W7-T1 meant to
    remove, and on 3.1 it hits at once, because the recursion-sys build dir exists without `metal/`.
    The loop now uses `if`, so a missing crate reaches the named error (rc 2).
  - `EMIT_IR_UNITS` (default `rv32im recursion keccak zkp groth16`) selects the units. Only the
    selected generated units need an `OUT_DIR`.
  - The shared headers come from rv32im's `OUT_DIR/_sys_` when it exists, else from
    `risc0/build_kernel/kernels/metal`. build_kernel writes the same files there verbatim.
  - Unknown unit names are an error.
- `run_stress.sh`: new step `groth16_tierz` (section 3), a header that documents the tier-Z cases,
  `EMIT_IR_UNITS` passthrough, and the advice to run the whole script under one heavy `gpu-run`.

## 3. Tier-Z bypass stress (W7-T1 open issue 1)

The IR guard of each flagged function, from `ir_scan.json` (`-gline-tables-only` build):

| function | guard (IR) | bypass forced by |
|---|---|---|
| `eltwise_sum_fpext` | `to_add == 0` skips `for i < to_add` | `to_add = 0`; counts 1, 3, 31, 33, 257 (threads past `count`) |
| `eu2_reduce` | `threadIdx < S` | S = 1..16 (threads >= S skip the loop); S = 32, 64 are controls |
| `batch_evaluate_any` | `K - 1 > -1`, K = ceil(deg / 256) | deg 0 (all threads skip; direct dispatch, since the HAL never passes deg 0); tiny deg 1..128 also skip the in-loop add on most threads |
| `msm_window_reduce_{g1,g2,g1w,g2w}` | `nsegs > tid` (loop entry) | nsegs < threadgroup width (<= 64): n 1, 3, 33, 1000; all-zero scalars (np = 0, every thread skips); scalars < 2^16 (windows >= 1 empty); seg 512 at n 4096; c = 4 seg 1 |

Tests:

- zkp: `tests_r17::r17_tierz_bypass` (ignored, in run_stress's `zkp` step). 33 shapes, each run
  `R17_TIERZ_REPS` times (default `max(R17_AUDIT_REPS, 20)`). The output is pre-filled with garbage,
  and every rep is compared with the CPU HAL and with rep 0.
- groth16: new `groth16-sys/src/metal/tests_tierz.rs`, enabled by environment so it can run inside the
  default parallel harness (without the variables the tests return at once):
  - `tierz_msm_window_bypass` (`R17_TIERZ_REPS` >= 20): 9 shapes x 3 tunes (default wide+Booth,
    wide unsigned, G6 `_g1/_g2`) x scalar bits 254/256 x G1/G2. Every rep is a sort plus both MSMs,
    compared with arkworks.
  - `tierz_g14_repeat` (`R17_TIERZ_G14_REPS` >= 50): g14_witness_like_scalars' inputs and tunes
    (witness-like 2^18 at c 16 and c 11, all ones 2^18 (c 11) and 2^17, all r - 1 at 2^17), bits
    254/256, against arkworks. `R17_TIERZ_G14_CASES=i,j` runs a subset.
  - run_stress's `groth16_tierz` step runs both.

## 4. NTT

- `tests_z9::z9_ntt_split_sweep` (W7-T1 open issue 3) skips splits that
  `test_hooks::split_violation` refuses, and prints how many it skipped, instead of panicking at the
  first one. At `Z9_LG=18 Z9_COLS=8 Z9_PAIRS=1`: GS lg 18 ran 18 splits and skipped 31; CT lg 20 ran
  26 and skipped 23 (`z9_sweep.log`).
- `split_tests::split_rules_match_gpu` (W7-T1 open issue 4) now requires `GPU_RUN_MODE`. After the
  1-column exhaustive pass it re-runs **every accepted split** at `NTT_SWEEP_COLS` (default 3, 211)
  columns, against sppark's split at the same column count. Two knobs:
  `NTT_SWEEP_COL_MAX_ELEMS` (default 2^28 elements per buffer) skips the larger (cols, lg) pairs and
  prints them. `NTT_SWEEP_ONE_COL=0` takes the accepted set from the rule alone.
- On 3.1 (`split_sweep_1.log`, 17 s, peak footprint 7.66 GB):
  - one column: 1630 splits, 1254 wrong, 34 exact but refused (all lg 11-12), **0 wrong accepted**.
    This is identical to W7-T1 on 3.0.
  - 3 columns: all 342 accepted splits of lg 11..22 are exact.
  - 211 columns: 228 accepted splits of lg 11..20 are exact; lg 21-22 were over the default cap.
  - The 211-column lg 21-22 run (`NTT_SWEEP_ONE_COL=0 NTT_SWEEP_LGS=21,22 NTT_SWEEP_COLS=211
    NTT_SWEEP_COL_MAX_ELEMS=1073741824`, `split_sweep_211_big.log`): 114 accepted splits, 0 wrong,
    **peak footprint 21.4 GB** (huge class; the HAL pool keeps the large buffers).
  - So every accepted split of lg 11..22 is exact at 1, 3 and 211 columns.
- One GPU fault: the first attempt at the lg 21-22 run, with the 1-column exhaustive pass, failed
  with `kIOGPUCommandBufferCallbackErrorPageFault` while it swept the **refused** GS lg 21 splits
  (CT lg 21 had finished). The same splits ran without a fault in `split_sweep_1.log`. Refused splits
  never reach `set_split`, so production is not affected. But a wrong split can read out of bounds,
  and whether that faults depends on memory placement (W7-T1 saw the same with 4 passes). That is
  why `NTT_SWEEP_ONE_COL=0` exists.
- Gate: `cargo test -p risc0-zkp --features metal --lib -- ntt:: tests_z13 tests_z9`, default
  parallel harness, heavy lock, twice: **11 passed, 0 failed** both times (`ntt_gate_{1,2}.log`).

## 7. Correctness, isolation, budgets, knobs

- Bit-exactness: every new stress case compares with the CPU HAL (zkp) or arkworks (groth16); the
  NTT sweep compares with sppark's split, whose CPU equality the existing NTT tests establish.
- Isolation (PLAN 8.7): the groth16 tests take `test_lock::shared` (as `msm_tests.rs`). The full
  groth16-sys suite with them enabled passed twice under the default parallel harness. The zkp
  test is ignored and runs with `--test-threads 1` in run_stress. No test sets process env.
- Memory: zkp tier-Z test is small (< 0.1 GB of buffers). groth16 tier-Z uses at most n 2^18
  points. The NTT sweep default is heavy (7.66 GB footprint); the 211-column lg 21-22 run is huge
  (21.4 GB). No prover path or default budget changed, so nothing is measured at the 4/8 GiB budgets.
- Knobs: `R17_TIERZ_REPS`, `R17_TIERZ_G14_REPS`, `R17_TIERZ_G14_CASES`, `NTT_SWEEP_COLS`,
  `NTT_SWEEP_COL_MAX_ELEMS`, `NTT_SWEEP_ONE_COL`, `EMIT_IR_UNITS`. `RISC0_METAL_NTT_SPLIT_CHECK=0`
  stays the revert knob for W7-T1's split rules.
- Clippy: no warning in the changed files. groth16-sys `--tests` has 2 pre-existing
  `type_complexity` errors in `coeffs.rs`/`srs.rs`, which are also present without this change.
