# G4: small Groth16 kernels (eltwise, witness_into_poly, ChaCha fuzz, powers)

Branch `metal/G4`, based on `zkminer/metal` (`5adc24fcf`, G1 + G2 merged). Scope: PLAN.md 4.5 row
G4 and the kernels-table rows `fr_mul`/`fr_mul_sub_from_mont`/`fr_add`, `witness_into_poly`,
`chacha_fuzz`, `fr_powers`/`fr_scale`.

Design points:
- One thread per element/row/block, `dispatch_threads` with 256-wide threadgroups
  (`[[max_total_threads_per_threadgroup(256)]]`), bounds-checked; the CUDA grid-stride loops become
  plain 1-D grids. All arithmetic is G2's `bn254::Fr` (32-bit CIOS); no 64-bit integer math.
- `fr_mul_sub_from_mont` always converts out of Montgomery form (the name's contract; CUDA's
  `coeff_wise_mul_and_sub` without the conversion is `fr_mul_sub_from_mont` minus the last step
  and is not provided).
- `fr_powers` computes `scale * base^j` (start value = scale instead of one, free): twiddles use
  scale = 1, the coset table `n^-1 * shift^j` is one pass instead of Intel's powers + scale.
  The 32-entry square table (1 KB) is built on the host with ark and passed via `set_bytes`
  (struct of u32 words, loaded with `Fr::from_limbs(constant ...)`).
- `chacha_fuzz` keeps the CUDA layout bit for bit: block i -> v0 = words 0..7, v1 = words 8..15,
  `l[7] &= 0x1FFFFFFF`, `idx = lane + wid * 64` with lane/wid from the CUDA WARP_SZ = 32 (not the
  Metal SIMD width), `out[idx] = v0`, `out[idx + 32] = v1` iff `idx + 32 < 2 * blocks`. CUDA
  bzeroes the buffer first; here the grid is `blocks` rounded up to 32 and threads `i >= blocks`
  write the zeros at their two slots, so every slot of `[0, 2 * blocks)` is written and no fill is
  needed. Consequence of the CUDA layout, reproduced: with a partial last warp some slots are 0
  (e.g. n = 2 scalars -> 1 block -> fuzz[1] = 0).
- `witness_into_poly`: Coeff is the 48-byte sppark `coeff_t` (`m, c, s, pad, Fr value`), as the
  Intel `Coeff`. Sequential per-row sum in CUDA order. Rows with no coefficients write nothing
  (CUDA would store to an uninitialised `coeff.c`; Intel skips them, as here). The coefficient
  file is untrusted for addressing: `fault` (u32, ORed) bit 1 = row range not monotone / past the
  array (row skipped), 2 = `s >= witness_len` or `c >= out_len` (row skipped), 4 = non-canonical
  value or witness element (row computed). `out` must be zero-filled by the caller.
- Host API (`small.rs`): `SmallKernels::new(device, library)` builds the 7 PSOs; each wrapper
  only **encodes** one dispatch into a caller's `&ComputeCommandEncoderRef` (G7 owns the command
  buffer boundaries). Buffers are `BufSlice { buf, offset }` (`BufSlice::fr_at(buf, index)`),
  lengths/offsets are checked against `buf.length()` (panic = programming error), counts must fit
  u32. Helpers: `fr_to_words`/`fr_from_words` (ark Fr <-> GPU words: ark's in-memory Montgomery
  limbs, R = 2^256, identical to bn254.h), `fuzz_blocks(n)`, `chacha_state(key, nonce)` (CUDA's
  `initialize_chacha_state<uint32_t>`), `Coeff`, `witness_fault::*`, `SMALL_KERNEL_NAMES`.
  groth16-sys does not depend on risc0-zkp, so `MetalHal` is not usable here; the wrappers take
  raw metal-rs objects (they work with `MetalHal::with_encoder` too if G7 ever wants that).

New tests (every output word compared):
- `eltwise_vs_ark`: fr_mul (out-of-place and in place), fr_mul_sub_from_mont (vs ark
  `(a*b - c).into_bigint()` limbs), fr_add, fr_scale (out-of-place and in place, by raw p-1 and a
  random scalar) on 22x22 edge pairs + 100000 random pairs (every 1000th b = a, b = -a). Edges:
  0, 1, 2, p-1, p-2, (p-1)/2, (p+1)/2, 2^32-1, 2^64, 2^128, 2^253 both as values and as raw
  Montgomery limbs. Slices at a 7-element offset with 0xdeadbeef guards before and after (no
  out-of-range writes); tail sizes 1, 2, 255, 256, 257, 1000 checked not to write past n; n = 0.
- `powers_vs_ark`: zero/one/-one/random bases, random scales, n in {1, 2, 5, 257, 300, 2^16+3},
  NTT tables for lg 1, 2, 10, 16 (omega^j, omega^-j for j < n/2, n^-1 * omega_2n^j for j < n,
  roots from ark `get_root_of_unity`) vs ark sequential products, guard after n; n = 2^22 spot
  values vs ark `pow` (j up to 2^22 - 1) and the chain every 4099th element.
- `fuzz_vs_chacha8_reference`: **every n = 1..=5000** (blocks 1..=2500, full and partial warps)
  against a reference built from `rand_chacha::ChaCha8Rng::from_seed([0; 32])` (stream words
  16 i .. 16 i + 16 = block i) laid out with the CUDA formula; buffer prefilled with 0x5a5a5a5a,
  so the zero slots and a 64-element guard past `2 * blocks` are checked; n = 2^20 + 5 full
  compare and every value < r. `chacha_state_matches_cuda_init` checks the initial state words.
- `witness_into_poly_vs_ark`: rows 1, 2, 257, 20000 with 0..=6 coefficients per row (empty rows
  included), one 1000-coefficient row, permuted output rows, 9 never-written outputs, values incl.
  0 and -1; coefficient and index slices at non-zero offsets (as the prover's B part); reference =
  ark sum of `Fr::new_unchecked(w) * Fr::new_unchecked(v)` (the GPU multiplies the raw words as
  Montgomery elements, as CUDA does). fault = 0.
- `witness_into_poly_faults`: s out of range, c out of range, end index past the coefficients
  (each: exact fault bit, rejected row unwritten, all other rows exact), non-canonical value
  (fault 4, other rows exact).
- `word_conversion_matches_ark`, `small_throughput` (below).

## Measured (indicative: M5 Max 40-core, other agents using the GPU; best of 3, command-buffer GPU time)

`RISC0_G16_SMALL_LG=<lg> cargo test -p risc0-groth16-sys --features metal --lib small_throughput -- --nocapture`

| n | fr_mul | fr_add | fr_mul_sub_from_mont | fr_scale | fr_powers | chacha_fuzz (n/2 blocks) | witness_into_poly (n/2 rows x 4) | current_allocated_size |
|---|---|---|---|---|---|---|---|---|
| 2^20 | 0.27 ms | 0.25 | 0.37 | 0.20 | 2.34 | 0.04 | 0.61 | 227 MiB |
| 2^22 | 3.6 | 1.0 | 2.3-2.5 | 0.76 | 10.0 | 0.3 | 3.2-3.5 | 905 MiB |
| 2^24 | 5.5 | 4.1 | 5.7 | 3.0 | 42.9 | 1.5 | 11.6 | 3617 MiB |

(The fr_mul 2^22 figure is noisy; the 2^24 one is the better bandwidth estimate.) Peak GPU memory
is just the test's buffers (inputs, out, coefficients; the kernels allocate nothing); in the
prover the persistent costs are the fuzz buffer (2 * fuzz_blocks(witness_len) Fr, ~32 B per witness
element) and the twiddle/coset tables (n/2 + n/2 + n Fr = 64 B per domain element), owned by G5/G7.
`fr_powers` (~23 dependent multiplications per element at 2^22) is a one-time table build per
domain; a strided-start variant would be ~10x faster if it ever shows up in a profile (G9).
Nothing depends on the core count (1-D grids, 256-wide groups).

## Assumed / not verified

- Ark Montgomery compatibility of the coefficient file's values / the witness format: the kernels
  multiply raw words exactly as CUDA's `fr_t` does; whether the file stores values so that the
  product is the intended one is the CUDA prover's contract (G3/G7 settle it end to end).
- The CUDA kernel itself was not run (no NVIDIA GPU); "bit-exact with CUDA" means bit-exact with
  its source formula (layout, mask, counter increment), as Intel's port is.
- PSO creation time is negligible (the whole 17-test suite runs in ~3.3 s incl. G2's), not
  measured separately.

## Issues for later items

- **G7:** the fuzz buffer needs `2 * fuzz_blocks(witness_len)` elements (more than witness_len);
  `chacha_fuzz` writes all of it, no prior fill. `witness_into_poly` needs `out` zero-filled
  (blit fill) and a zeroed `fault` u32 read after the batch; bail on non-zero. Use
  `fr_mul_sub_from_mont` for H (it already converts for the MSM), `fr_add` for witness + fuzz.
- **G3:** small.rs defines `Coeff` (48-byte `#[repr(C)]`, `value: [u32; 8]`); if G3's coeffs loader
  defines its own, G7 should keep one (the layout is static-asserted on both sides).
- **G5:** `fr_powers(out, n/2, omega)`, `fr_powers(out, n/2, omega^-1)`,
  `fr_powers(out, n, omega_2n, scale = n^-1)` build the Intel `NttPlan` tables in three dispatches.
