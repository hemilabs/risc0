## What was ported (from `recursion-sys/kernels/cuda/ffi.cu`)

`HostAccumContext` on the `SPPARK_NO_COOPERATIVE_LAUNCH` path (ffi.cu:1400-1590) and
`risc0_circuit_recursion_cuda_accum` (ffi.cu:1897-):

- constructor with `device_fill` (`fillOneExt<<<..>>>(g_accumCache.accum, workCycles)`, 1445-1447);
- `computeAccum` (`parStepComputeAccum`, 1491-1495);
- `calcPrefixProducts`, own-scan branch (1525-1541): `prefixProductsChunks` as exactly
  `ceil(n/2048)` groups of 256 threads, `prefixProductsTotals` (1 thread) and `prefixProductsFixup`
  (`n - 2048` threads) only when `nblocks > 1`; totals buffer = ceil(n/2048) FpExt (C1 note);
- `verifyAccum` (`parStepVerifyAccum`).

All encoded into the HAL's open batch with no host wait between them (CUDA syncs the stream after
each step; not needed here: one serial compute encoder, hazard-tracked shared buffers), preceded by
the fault-word blit (`fault_word()`), followed by one `check_fault(.., Phase::Accum)` (sync + read +
`bail!`). Binding order per C1 context.h / C2 note: 0 ctrl, 1 global, 2 data, 3 mix, 4 accum group,
5 accumTmp, 6 fault, 7 `RecAccumParams {totalCycles, workCycles, 0, 0}` (16 B, `bytemuck::NoUninit`,
size const-asserted). `exclusive()` taken per call (reentrant; `Prover::run` already holds it).

Added beyond CUDA (plan 2.9): host checks before encoding (bail, nothing encoded):
`total_cycles` a power of two (steps use `mask = steps - 1`), `work_cycles <= u32::MAX - 2048`
(C1's 32-bit scan index range), and each of ctrl/data/accum >= `group_size * total_cycles`,
global >= 32, mix >= 20 elements. `work_cycles > total_cycles` is left to C2's kernel guard (thread 0
sets fault 1), which the tests exercise. `work_cycles == 0` returns early (the CPU accum does
nothing either).

Debug aid: `RISC0_METAL_REC_ACCUM_CHECK=1` (read once; tests use `FORCE_ACCUM_CHECK`) copies the
five inputs to host vectors before encoding, then runs `risc0_circuit_recursion_cpu_accum` on them
and fails on the first raw-word difference in accum or global (`ACCUM_CHECKS_OK` counts passes).
Comparison is on Montgomery words: `BabyBearElem ==` asserts validity and the accum group holds
INVALID cells.

`CircuitHal::accumulate` (zkp trait, errata 8.4) stays `unimplemented!()` exactly like cuda.rs and
hip.rs: it lives in `eval_check.rs` (C8's file) where C5 already put it; recursion accumulates only
through `CircuitAccumulator`.

### Tests (`c7_tests` in accum.rs; C9 owns `hal/metal/tests.rs`)

Inputs are a **real** witness: `test_recursion_circuit.zkr` preflight + CPU `WitnessGenerator::new`
at the given po2 (ctrl, data, global with `valid_or_zero` as the prover's header applies), a random
mix, accum INVALID with random noise in the last `ZK_CYCLES` rows (as `WitnessGenerator::accum`
leaves it). The test program has only 211 code rows, so n > 211 tiles the live ctrl/data rows
cyclically (the accum steps read only the row's ctrl/data, the mix and the running product; the
GPU never faulted and the CPU asserts never fired on tiled traces). Random field inputs were tried
first and are **not** usable: random ctrl/data trip the verify step's asserts on both backends
(the CPU's `assert` aborts the process). Metal runs first (an error is clean), then the CPU; accum,
global and data are compared word for word; dead rows must stay INVALID and noise rows untouched.

- `accum_matches_cpu_scan_edges`: n = 1, 2, 2047, 2048, 2049, 4097 at po2 16; n = 100001 at po2 17.
- `accum_matches_cpu_full`: the program's own 211 rows at po2 16 and 18; n = 2^18 - ZK_CYCLES
  (= 261120, the lift/join shape) at po2 18; n = **2^18** at po2 19. Each also re-runs Metal on the
  same HAL and requires identical output.
- `accum_scan_blocks`, `accum_work_zero_is_noop`.
- Fault path: `accum_fault_on_invalid_input` (row 100 of every data column set to INVALID → `Err`
  containing `Accum` and `kernel fault`; the same HAL then runs a clean accum);
  `accum_fault_on_bad_shape` (work 5 > total 4 → `kernel fault 0x00000001` from the C2 guard;
  total 3 → "power of two"; buffers for 4 rows with total 8 → "needs").
- `accum_real_trace_shadow_check`: full Metal-HAL proofs of the test zkr at po2 16 and 18 with the
  shadow check forced: the proof's accum equals the CPU accum, output equals the CPU prover's.

## Measurements (M5 Max, GPU shared with other agents: indicative)

Peak device memory (`currentAllocatedSize`, process-wide):

| shape | before | peak (accum test incl. its uploaded inputs) |
|---|---|---|
| po2 16, n ≤ 4097 | 6.0 MB | 48.8-48.9 MB |
| po2 17, n = 100001 | 6.0 MB | 93.5 MB |
| po2 18, n = 211 / 261120 | 6.0 MB | 177.0 / 182.2 MB |
| po2 19, n = 2^18 | 6.0 MB | 353.1 MB |
| full proof, test zkr po2 16 / 18 | | **371 MB / 1.44 GB** (identical to C5's CPU-accum numbers) |

The accum's own scratch is 16 B x n + 16 B x ceil(n/2048) (4.2 MB at n = 2^18, with 25 %
headroom 5.2 MB); everything else it touches already exists. Identical numbers under the 4 GB and 8
GB budgets: **no tested shape exceeds either budget**, so no budget error was produced (the clean
over-budget error path was shown by C5 at 1 GiB and is unchanged).

`accumulate` wall time (no uploads/readback), Metal second call on the same HAL vs CPU (poolstl,
all cores): n = 1: 1.9 ms vs 0.07 ms; n = 2049: 3-10 ms vs 0.5 ms; n = 100001: 18 ms vs 20-113 ms;
n = 261120: 24 ms vs 65-72 ms; n = 2^18 (po2 19): 8.5-33 ms vs 38-64 ms. The first call on a fresh
HAL costs 15-140 ms more (first touch of new pool buffers and the first command buffers). Small n
is dominated by the fixed per-batch cost (~2 ms); real lift/join run n ≈ 2^18.

## Known gaps

- No dedicated GPU-vs-CPU test on an actual lift or join witness inside the recursion crate (the
  crate has no lift input); lift/join are covered by the zkvm e2e run with the shadow check.
- Tiled traces exercise the scan at large n with real row contents, but not the exact cross-row
  values of a 2^18-row program.
- Totals is a single-thread serial scan (C1/CUDA); at n = 2^18 that is 128 FpExt multiplies, not a
  concern. A `simd_prefix` scan and fusing fill into compute are C11 items.
- Per-call cost floor (~2 ms) and the first-call cost were not profiled.
