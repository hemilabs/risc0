### stepAccumA ABI (for R9)
```
0 data   device Fp*  (dataRows x dataCols, column-major, rows power of two)
1 accum  device Fp*  (accumRows x accumCols, rows power of two)
2 global device Fp*  (globalRows x globalCols, row 0 used)
3 mix    device Fp*  (mixRows x mixCols, row 0 used)
4 perm   const device uint*  (read only if hasPerm; else bind any buffer, e.g. accum)
5 fault  device atomic_uint* (1 word; bits ORed once per thread)
6 AccumParams (set_bytes, 48 B): count, hasPerm, dataRows, dataCols, accumRows, accumCols,
  globalRows, globalCols, mixRows, mixCols, _pad[2]   (all u32; static_assert'ed 48 in MSL)
grid: dispatch_threads(count), threadgroup <= pso.maxTotalThreadsPerThreadgroup (256)
```
- `[[max_total_threads_per_threadgroup(ACCUM_TG)]]`, ACCUM_TG = 256 (CUDA `__launch_bounds__(256, 1)`).
- `cycle = hasPerm ? perm[gid] : gid`; a perm entry `>= count` sets **`RV32IM_FAULT_ACCUM_PERM = 0x20u`**
  (new bit, defined `#ifndef` in accum_tu.metal; R1's `cuda_compat.h` should adopt it) and skips the row.
- The accum graph calls no extern except `assert` (grep of accum_tu.cu: 635 `INVOKE_EXTERN(ctx, assert`,
  no lookups/preflight), so the kernel binds neither preflight nor lookup tables (the ffi.cu comment
  "only uses lookupDelta/lookupCurrent" is stale): it builds a null `PreflightTrace` and
  `makeLookupTables(nullptr, nullptr)`. `C2M_ASSERT` bits (`tables.bad`) are ORed into `fault`.
- `kUserAccumSplitA` = `kLayout_TopAccum.columns.elems[0].col` (`constant constexpr uint32_t`, R3 rule).
- Buffer objects: `makeMutableBuf(data)`, `makeMutableBuf(accum, nullBuffer(), kUserAccumSplitA)`,
  `makeGlobalBuf(global/mix)`; call `step_TopAccum_A(ctx, &accum, &data, &global, &mix)` as CUDA.

## Measurements (go/no-go)

Harness: `/private/tmp/claude-501/-Users-user-zkminer/a30bccea-eec8-43d4-ac51-c5ccb6e4b957/scratchpad/r4/pso`
(metal-rs 0.29, not committed: loads a metallib, times `new_compute_pipeline_state_with_function(stepAccumA)`,

| always, cargo-built crate metallib | 256 | (in 21.8 s crate build) | — | — | 94.2 s | 0.002 s | 256 / 32 | 0 |

- **Register/occupancy**: the compiler grants the full declared size in every case (with a 1024 cap it
  still reports 1024), so register pressure does not cut the threadgroup limit; Metal exposes no
  register count. 256 stays (CUDA's bound; 1024 doubles the always-inline cold PSO).
- **Cold PSO variance**: the same always/256 configuration took 52 s in the scratch build and 94 s for
  the crate metallib (machine load from other agents). Treat cold PSO as **~40-95 s** on the M5 Max; a
  base 8-10-core Mac's CPU compiler service will be slower. It is a one-time cost per metallib content
  (OS shader cache), comparable to keccak's 94 s (K3).
- **Shader cache is written asynchronously**: always/1024's second run, started right after the cold
  one, was cold again (91.5 s); the third run was warm. M1/K5 warm-up should not assume the cache is
  populated the instant `new_compute_pipeline_state` returns.
- **Dispatch (indicative only, shared GPU)**, tg 256, hasPerm, random data: po2 16: always 1.5 ms,
  noinline 1.8 ms; po2 18 (crate lib, always): 4.2 ms; po2 20: always 6.6 / 13.4-14.2 ms, noinline
  3.9-4.7 / 14.7-16.1 ms across two runs. No ranking can be drawn; R15 owns the sweep.
- **Peak GPU memory** (`current_allocated_size`, harness owns only these buffers: data 211 cols, accum
  103, global 90, mix 36, perm, fault): po2 16 → 81 MB, po2 18 → 317 MB, po2 20 → 1262 MB; unchanged by
  the dispatch (the kernel allocates nothing; no threadgroup memory). R9's accum phase adds its scratch.

**Decision: GO for `always`** (CUDA parity; compile 12 s + 3 s link, well within budget). `noinline`
is a working fallback (lower cold PSO, slower metallib link only for always) selectable with
`RISC0_METAL_ACCUM_INLINE=noinline`; both compile, both give identical output.

## Assumed / not verified
- No CPU-equivalence check of stepAccumA output (R9). The translation is by construction the same
  statements as accum_tu.cu, and always/noinline agree bit-for-bit on random inputs.
- Cold PSO time on the 16 GB / 8-10-core minimum target was not measured (no such machine).
- `[[clang::always_inline]]` vs `__attribute__((always_inline))` are the same attribute; the probe
  (`attr.metal`) compiled with `-Werror`. Whether the Metal backend fully inlined every call was not
  inspected beyond the larger link time and smaller .air.
