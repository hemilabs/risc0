## What it does

`cuda2metal.py` is a sequence of counted text passes over the generated CUDA (comment- and
string-masked, bracket-aware; no compiler front end). Anything it cannot translate faithfully
raises `TranslateError`; a final residual scan refuses output that still holds a CUDA-only
construct (`__device__`, lambdas, `::value_type`, structured bindings, `cuda::std::`, `asm`,
`nvtx`, `map(`/`reduce(`, `assert(`, unqualified `ExecContext&`, `Fp**`, the CUDA namespace).

| Pass | Source construct (where it comes from) | Metal output |
|---|---|---|
| `kernel` | `__global__` kernels, `__launch_bounds__(N[,M])` before or after `__global__` (ffi.cu:674, eval_check_kernel.cu:46, witgen_tu.cu:18983) | `[[max_total_threads_per_threadgroup(N)]]` **before** `kernel void` (macro arg → `C2M_LB_FIRST(X)`, which takes the first of a `256, 8` expansion); pointers `[[buffer(i)]]` with the policy address space; scalars `constant T& x [[buffer(i)]]`; default args dropped; the `threadIdx/blockIdx/blockDim/gridDim` uint3 attributes that the body uses (ntt.metal precedent); a `// buffer(i): ...` table above the kernel. A kernel inside a namespace is hoisted to global scope (namespace closed/reopened around it, `using namespace` before it): a namespaced kernel's entry is `rv32im_metal::eval_check` (checked with `metal-nm`), not `eval_check`. |
| `strip` | `__restrict__`; `nvtx3::scoped_range r(...)`/`nvtxRange*` (ffi.cu:1539); `asm("")` barriers and asm-comment templates (eval_check_ef_hip.cu:395, `EF_OPQ`) | removed. An `asm` with instructions (eval_check_ef.cu:235 `mad.wide.u32`) is an error, never stripped. |
| `include` | `#include "steps.cuh"`, `"witgen.h"`, CUDA system headers; namespace `risc0::circuit::rv32im_v2::cuda` | `"steps.metal.h"`, `"witgen.h"`, dropped; `rv32im_metal` (R1's witgen.h namespace). Unknown includes are errors. |
| `accum_guard` | steps.cu:48296/66123 `#ifdef __HIPCC__ // CUDA: stepAccumA ...` fence (accum_tu_gen.py) | `#ifndef RV32IM_METAL_STEPS_NO_ACCUM` (accum part compiled by default) |
| `array` | `::cuda::std::array<` (types.cuh.inc ×99) | `r0::array<` (cuda2metal.h) |
| `value_type` | `X::value_type` (steps.cu ×86) | element type of `X` from the `using X = array<T, N>` typedefs of types.cuh.inc (unknown `X` is an error) |
| `sbind` | `auto [a, b, ...] = INVOKE_EXTERN(...)` (steps.cu ×6: lines 894, 1489, 9457, 16496, 16533, 18325) | `auto c2m_sbK = ...; auto a = c2m_sbK[0]; ...` |
| `lambda` | `T x = map(a, [b,] ([&](...) {...; return e;}))` ×42 and `T x = reduce(elems, start, layout, ([&](...){...}))` ×1 (steps.cu:7292) | `auto c2m_aK = a; [auto c2m_bK = b;] T x; for (uint c2m_iK = 0; c2m_iK < c2m_aK.size(); c2m_iK++) { P0 p0 = c2m_aK[i]; P1 p1 = LAYOUT_SUBSCRIPT(c2m_bK, i) or c2m_bK[i]; body; x[i] = e; }`; reduce keeps `auto c2m_accK = start;` and assigns `T x = c2m_accK;`. Same evaluation as witgen.h's map/reduce templates (arguments copied once, elements in index order, layout element via `LAYOUT_SUBSCRIPT` = the template's `BoundLayout(b.layout[i], b.buf)`). Innermost site first, so nested sites work. Exactly one top-level `return` that is the last statement is required (else error). |
| `fpp` | `Fp** args` (eval_check_ef.cu:16615 `poly_fp`, prototypes :339 etc.) | `device Fp* args_0, ..., args_{K-1}` with K = 1 + largest literal index in the definition; `args[k]` → `args_k`; prototypes take K from the definition; any non-literal use is an error |
| `qual` | `__device__` fns, `extern __device__` prototypes, `static __device__`, `__device__ constexpr` data (layout.cu.inc ×1194), namespace-scope `constexpr` (defs.cu.inc ×6), `__noinline__`, `__forceinline__`, `__host__`, `__constant__` | removed / `static` / `constant constexpr` / `__attribute__((noinline))` / `inline __attribute__((always_inline))` / `constant`. `extern __device__` data is an error (Metal has no extern program-scope data). |
| `aspace` | pointers/references in signatures, locals and casts | per `ASPACE_POLICY` (below) |
| `fp_zero` | `Fp x = 0;`, `x = 0;` for Fp/Val/FpExt/ExtVal locals and params, `return 0;` in Fp-returning functions (witgen.h:128 `MutableBufObj::load`) | `T(0)` |
| `assert` | `assert(c)` (steps.cu ×134, all `assert(0 && "Reached unreachable mux arm")`) | `C2M_ASSERT(ctx, c)` → `ctx.tables.bad |= RV32IM_FAULT_ASSERT (0x10)` when `c` is false (plan 2.9: R1's kernels OR `tables.bad` into the fault buffer once per thread); no `ctx` in scope → `C2M_ASSERT_NOCTX(c)` = no-op (CUDA release). `INVOKE_EXTERN(ctx, assert, ...)` is untouched (witgen.h's no-op `extern_assert`). |

Address-space policy table (`ASPACE_POLICY`):

| Types | `*` / `&` | Address space | Why |
|---|---|---|---|
| ExecContext, PreflightTrace, LookupTables, BufferObj, MutableBufObj, GlobalBufObj, Buffer | both | `thread` | per-thread objects the kernel builds |
| `BoundLayout<...>` | `&` | `thread` | bound layouts are thread values |
| `char` | `*` | `constant` | string literals |
| Fp, Val, FpExt, ExtVal, uint32_t, uint, int32_t, PreflightCycle, MemoryTransaction | `*` | `device` | every buffer is device (plan 2.1) |
| PreflightCycle, MemoryTransaction | `&` | `device` | element of a preflight buffer (`const PreflightCycle& c = cycles[row]`) |
| Fp, Val, FpExt, ExtVal | `&` | **error** | may alias a thread local or a buffer element: must be spelled |
| DeviceExecContext, DeviceAccumContext(A), WmsInject | both | **error** | struct of device pointers; Metal kernels take explicit bindings (plan 2.0), R4/R5 hand-write those wrappers |

Kernel parameters: pointer → policy space (`thread`/unknown/error rows refused), reference → `constant`, by-value scalar → `constant T&`.

Output prelude (in `steps.metal`, before `namespace rv32im_metal`): the `C2M_ASSERT` /
`C2M_ASSERT_NOCTX` / `RV32IM_FAULT_ASSERT` / `C2M_LB_FIRST` macros, and mixed `Fp ± FpExt`,
`FpExt ± Fp` operators (see gaps) guarded by `C2M_NO_FPEXT_MIXED_ADDSUB`.

CLI: `--selftest [--headers DIR] [--keep DIR]`; `steps -o DIR [--compile] [--headers DIR]
[--check] [--no-pin]`; `incs -o DIR [--check]` (defs/types/layout `.metal.inc`, needed to
compile the steps output; R3 owns the build wiring of these files); `file IN -o OUT`. The module
is importable (`translate()`, `translate_steps()`, `translate_incs()`) for R3–R6's generators.
`--headers` defaults to `rv32im-sys/kernels/metal` when R1's `witgen.h` is on the branch, else to
the selftest stub.

## Selftest

`--selftest` (≈30 s wall, ≈14 s CPU):
1. Translates defs/types/layout incs and steps.cuh into a temp dir (the snippets compile against
   them), and the full steps.cu: counts must equal the pins.
2. Pin sensitivity: a steps.cu with one assert and one structured binding rewritten must report
   exactly `assert 134→133` and `sbind 6→5`.
3. One snippet per pass, extracted from the real sources by anchor, translated, counts checked,
   residual-scanned, and compiled with `xcrun -sdk macosx metal -std=metal3.2 -O2` against the
   headers + `build_kernel/kernels/metal`: `back_NondetReg` (qual/aspace), `OneHot` 3-arg map
   (value_type/lambda), `exec_DigestReg` (map returning a struct literal), the `DoIntRounds`
   reduce, the getMemoryTxn (5) and bigIntExtern (16) structured bindings, the shortest function
   with an unreachable-arm assert, the first `array` typedef of types.cuh.inc, witgen.h's
   `MutableBufObj::load` (`return 0;` → `Val(0)`), `injectCycleCols` (ffi.cu, kernel synthesis +
   namespace hoist) and `eval_check` (eval_check_kernel.cu, `__launch_bounds__` before
   `__global__`, truncated body) — both checked with `metal-nm` to be unmangled global entry
   points — `poly_fp`'s `Fp** args` definition + prototype (eval_check_ef.cu), and an asm("")
   barrier (eval_check_ef_hip.cu) + nvtx range (ffi.cu) + `__restrict__`.
4. Refusals: `par_stepExecW(DeviceExecContext*)` (witgen_tu.cu), `ef_madw`'s real asm
   (eval_check_ef.cu), a lambda with two returns, an unknown `::value_type`, `Fp&` param, an
   unmapped include.

## Assumed / not verified
- No GPU execution of translated code: lambda/structured-binding expansion is checked by
  construction (same statements, same order, same copies as witgen.h's templates) and by
  compilation only. R5/R8 (`witgen_matches_cpu`) and R4/R9 are the runtime gates.
- `steps.air` alone does not link into a metallib: the `extern_*` functions are declared, not
  defined (by design; D0: an undefined extern fails at `metallib` link). R5 defines them.
- The `aspace` pass recognises declarations by pattern (type from the table followed by `*`/`&`
  and a declarator); a multiplication spelled `Type * x` with a table type name on the left would
  be misread. The generated sources never do that; the selftest covers the shapes they use.
- `Fp(0)`: covers `T x = 0;`, `x = 0;` for Fp-typed locals/params, `return 0;` in Fp functions.
  A zero assigned to an Fp struct member (`s.f = 0;`) is not typed and not rewritten (none in
  the rv32im sources).

## Known gaps / hand-offs
- **fpext.h owner (F1 / zkp-hal)**: add mixed `Fp ± FpExt` operators to `fpext.h`; then define
  `C2M_NO_FPEXT_MIXED_ADDSUB` (or drop the shim) or the two overload sets become ambiguous.
- **R1/R3/R5**: adopt `RV32IM_FAULT_ASSERT 0x10u` in `cuda_compat.h` (the prelude defines it only
  `#ifndef`) and make sure every kernel running step functions ORs `tables.bad` into its fault
  buffer (R1's design already does).
- **R6 (eval mode)**: not handled here: `__constant__ FpExt poly_mix[N]` without initializer
  (becomes `constant` and will not compile: thread it as `const device FpExt*` per plan),
  `FpExt::operator[]` (`ret[0]` in eval_check_kernel.cu; Metal fpext.h uses `.elems[i]`), and
  `Fp**` call sites that pass a pointer array (`rk::poly_fp(..., args)`): only definitions,
  prototypes and literal indexing are rewritten.
- `HIP`-only `#ifdef` branches are ignored by function discovery (alternative headers would
  unbalance braces) but still emitted; the residual scan still sees them.
- steps.cu indexes with `size_t` (64-bit; `to_size_t`, `Index`) in 538 places; left as is
  (perf, not correctness: D0 measured 64-bit integer ops 4–5× slower). Candidate for R15.
