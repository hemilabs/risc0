## What was done
- `circuit/keccak/src/prove/hal/metal/witgen.rs` (new): the `CircuitWitnessGenerator` impl and
  `scatter_preflight_gpu` moved here from K1's `mod.rs`.
  - `scatter_preflight` now runs the GPU kernel (`scatter_preflight` in keccak-sys
    `kernels/metal/scatter.metal`, K1's 1:1 port of `kernels/cuda/ffi.cu:161-181`), as
    `CudaCircuitHal::scatter_preflight` (`hal/cuda.rs:84-101`) does: infos and packed words are copied
    into pooled shared buffers, one thread per info, `try_sync` at the end of the phase, and the fault
    flag turns a bad info into `Err` (CPU path: `assert!` panic). The CPU scatter is no longer on the
    Metal prover path (`host_witness()` still uses `scatter_preflight_host`, unchanged).
  - `generate_witness`: unchanged behaviour (CPU `generate_witness_host` into `view_mut` of the shared
    `global`/`data` buffers; `view_mut` waits for the scatter batch). `HOST_WITNESS = true`,
    `PreferredPreflightOrder = ForwardPreflightOrder` (errata 8.4 phase 1).
- `hal/metal/mod.rs`: `mod witgen;`, module doc updated. `CircuitHal::accumulate` is the no-op exactly as
  `cuda.rs:153-163` (keccak has no accumulation). `eval_check` stays the CPU `poly_fp` bridge over
  `view()`/`view_mut()` of the Metal buffers (ported from `CpuCircuitHal::eval_check`); `eval_check_dep`
  no-op. Drop: not needed (K1's reasoning stands).
- Test-only instrumentation (`#[cfg(test)]`): `tests::mark_phase(device, Phase)` called by the HAL on
  entering scatter / witgen / (witgen end → commit) / eval_check / (eval_check end → finalize). It counts
  phase entries per thread and, while a memory measurement runs, records `current_allocated_size`.
- Tests in `hal/metal/mod.rs`:
  - `metal_prover_runs_on_metal_hal` (K1's) now also asserts that `crate::prove::keccak_prover()` went
    through the Metal HAL's scatter, witgen and eval_check exactly once each (proves the HAL type).
  - `eval_check` (new): `testutil::eval_check` CPU HAL vs Metal HAL at PO2 4, random inputs, bit-exact
    (as cuda.rs `tests::eval_check`).
  - `metal_peak_memory` (new, `#[ignore]`): proves po2 `K2_MEM_PO2S` (default 8,12,14) on a fresh
    `MetalHalPoseidon2` prover, with a 100 µs sampler thread plus the phase-transition samples; prints
    the peak `current_allocated_size` per phase; seals verify.
- `prove/tests.rs`: `fwd_rev_ab` gained the `else if #[cfg(feature = "metal")]` branch
  (`MetalHalPoseidon2` + `MetalCircuitHalPoseidon2`), so under `--features metal` it compares SeqForward
  vs GPU-scatter + SeqReverse on the Metal HAL (with GPU zeroize). CPU branch untouched.

## Measurements: peak GPU memory per phase (`MTLDevice.currentAllocatedSize`, MiB)
Fresh `MetalHalPoseidon2` per po2, baseline after HAL + keccak PSO construction 1.8 MiB. Includes buffers
cached in F0's pool (an upper bound on live buffers). Prove times are indicative (shared machine).
| po2 | setup | scatter | witgen | commit | eval_check | finalize | overall peak | prove |
|---|---|---|---|---|---|---|---|---|
| 8 | 2.8 | 2.9 | 2.9 | 13.1 | 13.1 | 13.4 | 13.4 | 0.09 s |
| 12 | 18.9 | 19.6 | 19.6 | 108.8 | 108.8 | 125.6 | 125.6 | 0.22 s |
| 14 | 70.3 | 73.2 | 73.2 | 429.6 | 429.6 | 453.7 | 453.7 | 0.75 s |
Phases: setup = preflight + `data`/`global` alloc and INVALID fill; commit = zeroize, code/data/accum
commits, mix and the check buffer allocated before eval_check; finalize = after eval_check until the seal.
Growth is ~4x per 2 po2 (linear in rows); extrapolated po2 18 ≈ 7 GB (matches the plan's 7–8 GB
estimate) — above the 4 GB minimum-tier budget (PLAN 9.1), so the minimum tier needs po2 ≤ 17 for keccak
or pool trimming (not measured here).

## Assumed / not verified / gaps
- Peak memory not measured at po2 > 14 and not under `RISC0_METAL_MAX_WORKING_SET_BYTES` (Z6's knob).
- The phase peaks come from a 100 µs sampler plus samples at the HAL's phase transitions; a buffer that
  lives shorter than the sampling interval inside the zkp prover could be missed.
- `metal_peak_memory` must be run alone (it uses process-wide statics and the device-wide counter).
- eval_check is still the CPU (`poly_fp`, rayon): it dominates prove time at larger po2. K4 replaces it.
- Witness is still CPU (`HOST_WITNESS = true`); K6 owns the GPU witgen and `MetalPreflightOrder`.
