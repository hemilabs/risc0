## What it does

`python3 kernels/cuda/cuda2metal.py eval -o DIR [--compile] [--check] [--no-pin]` builds one
CUDA input from (in this order) `eval_check.cuh` (minus `#pragma once`), `eval_check_0.cu`,
`_1.cu`, `_2.cu`, `_3.cu` and the `eval_check` kernel cut out of `eval_check_kernel.cu`
(lines 15-17 `EVAL_CHECK_THREADS` default + 46-72 the kernel; `eval_check_diag`, the second
`__constant__ poly_mix` definition and all host code are not taken), and translates it with
`EVAL_PASSES = poly_mix, kernel, strip, include, fpext_index, fpp, qual, eval_aspace, fp_zero`
into `DIR/eval_check.metal` (27060 lines, 0.6 s). The file is rewritten only when its text
changes (so cargo does not rerun the build script). Counts are pinned in `PINNED_EVAL`.

| Pass | Source construct | Metal output |
|---|---|---|
| `poly_mix` (new) | `__constant__ FpExt poly_mix[kNumPolyMixPows];` (eval_check.cuh:306, no initializer; CUDA fills it with `cudaMemcpyToSymbolAsync`) | declaration → comment + `static_assert((kNumPolyMixPows) > 0)`; every function that uses `poly_mix` directly or through a call (transitive closure: all 21 + the kernel) gets a trailing `const FpExt* poly_mix` parameter on its prototype and definition, and every call site gets `, poly_mix`. The kernel thereby takes it as its last binding. An initializer is refused (that would be a real constant table). Functions that already have a `poly_mix` parameter are left alone. |
| `fpext_index` (new) | `ret[0]` on an FpExt value (eval_check_kernel.cu:68-71) | `ret.elems[0]` (Metal fpext.h has no `operator[]`). Only by-value FpExt params/locals of the same function are rewritten; FpExt arrays/pointers keep `[]`; subscripting an `auto` local is refused. |
| `fpp` (extended) | R2: `Fp** args` definitions/prototypes + `args[k]` | Now also call sites: an argument that is a local `Fp* a[N] = {p, q, ...};` becomes `p, q, ...` (first K), other `a[k]` uses become `(elem)`, the array declaration is removed; the caller's own Fp** parameter is forwarded as `args_0, ..., args_{K-1}` (K grows to the callee's K). Anything else is refused. The baseline eval chain has no `Fp**`; this serves evalfast-shaped code (`ef_eval_split`'s `Fp* args[5] = {...}; rk::poly_fp(..., args)`). |
| `eval_aspace` (new) | pointers in the chain signatures | `const Fp*` → `const device Fp*` (trace buffers + poly_mix); mutable `Fp*`/`FpExt*` → `thread` (poly_fp's `Fp x33[1007]` / `FpExt x34[144]` temporaries handed down the chain); `Fp&` refused. Kernel params already carry their space (pass `kernel`). |
| `include` (parameterised) | `"supra/fp.h"`, `"eval_check.cuh"`, `<cstdint>` | dropped (header inlined; `#include <metal_stdlib>`, `"fp.h"`, `"fpext.h"` emitted once at the top); namespace `risc0::circuit::rv32im_v2::cuda` → **`rv32im_metal_eval`** (not `rv32im_metal`, so the chain's `poly_fp` cannot collide with evalfast's or anything else in the metallib). |
| `kernel`, `qual`, `strip` | R2 passes as is | `[[max_total_threads_per_threadgroup(C2M_LB_FIRST(EVAL_CHECK_THREADS))]]` before `kernel void eval_check`, hoisted to global scope; 20 `__noinline__` → `__attribute__((noinline))` (prototypes), `INV_RATE`/`kNumPolyMixPows` → `constant constexpr`. |

Kernel ABI (for R10): `eval_check`, buffers
`0 check (device Fp*, 4*domain)`, `1 ctrl`, `2 data`, `3 accum`, `4 mix`, `5 out` (`const device Fp*`),
`6 rou (constant Fp&)`, `7 po2 (constant uint&)`, `8 domain (constant uint&)`,
`9 poly_mix (const device FpExt*, 458 = kNumPolyMixPows entries)`; index quartet
`threadIdx/blockIdx/blockDim` → `cycle = blockDim.x*blockIdx.x + threadIdx.x`, bounds-checked
against `domain` (dispatch_thread_groups with 256-thread groups, as CUDA). `ctrl` is unused by
poly_fp (as in CUDA). PSO: maxTotalThreadsPerThreadgroup 256, execution width 32, 0 static
threadgroup memory.

Other changes in cuda2metal.py:
- `header_name()` ignores `__launch_bounds__(...)` (it returned `__launch_bounds__` as the name of
  a kernel written `__launch_bounds__(N) __global__ void k(`; found when threading poly_mix).
- `PRELUDE` no longer carries R2's mixed `Fp ± FpExt` shim (dead since R3's fpext.h defines
  `C2M_NO_FPEXT_MIXED_ADDSUB`); `LB_PRELUDE` (`C2M_LB_FIRST`) is split out and used by both
  steps and eval output. steps.metal shrinks by 19 lines (66282 → 66263), counts unchanged.
- `translate()` takes `include_map=` and `metal_ns=`; new importable `translate_eval()`,
  `eval_input()`, `write_if_changed()`, `EVAL_*` constants.

build.rs R6 block: prints `rerun-if-changed` for cuda2metal.py, eval_check.cuh, eval_check_0..3.cu
and eval_check_kernel.cu; runs `cuda2metal.py eval -o $OUT_DIR/metal` (fails the build on a pin
mismatch with a hint); pushes `$OUT_DIR/metal/eval_check.metal` onto `generated`; nothing under
`RISC0_SKIP_BUILD_KERNELS`.

## Known gaps / issues for later items
- **R10:** bind as in the ABI above; poly_mix is a 458-entry `const device FpExt*` buffer
  (7328 B: above the 4 KB `set_bytes` limit). Use `dispatch_thread_groups(ceil(domain/256), 256)`.
  The 6.3 KB/thread private arrays are kept as `thread` arrays (plan 2.1 allows it when
  measured acceptable: it compiles, links, runs and is bit-exact up to po2 18); moving them to
  `device` scratch slices is an optimization, not needed for correctness.
- **R7/M1/K5 (cold start):** with `"eval_check"` in `METAL_KERNEL_NAMES`, R7's loader builds its
  PSO at the first circuit HAL construction: **~54 s cold** on the M5 Max for each new metallib
  content, instant after. `metal_warmup()` must run at install/first start, never inside a job.
  If that is unacceptable before R12, R7 could build the eval_check PSO lazily on first
  `require(EvalCheck)`.
- **R15:** `INV_RATE` is `size_t`, so `(idx - INV_RATE*k) & mask` is 64-bit math; a `uint32_t`
  `INV_RATE` gives the same low bits (mask < 2^32) and avoids the emulated 64-bit ops.
- **R12:** the `fpp` call-site rewrite emits `device Fp*` for every expanded pointer;
  `ef_eval_split` passes a thread slab (`args[4]`) next to device buffers, so evalfast's
  `to_metal.py` must give that position a `thread` space (or keep its own `EfCtx` design).
- `cuda2metal.py`'s `INCLUDE_MAP['"eval_check.cuh"']` (R2) still maps to `eval_check.metal.h`
  for the default mode; eval mode uses `EVAL_INCLUDE_MAP` and never writes that header.
