## What was done
- `circuit/keccak/src/prove/hal/metal/eval_check.rs` (new): the runtime of K3's staged kernels.
  Ported from the Intel launcher `keccak-sys/kernels/intel/kernels.h` (`risc0_circuit_keccak_intel_eval_check`
  lines ~117-170, `launch_eval_stage` ~82-100) with the inputs of `hal/cuda.rs` `eval_check` (165-221).
  - Chunked launcher: the domain goes through all `S` stages a chunk of `C` cycles at a time (`C` =
    32768 by default, `RISC0_KECCAK_METAL_EVAL_CHUNK` overrides, `MetalCircuitHal::set_eval_chunk` for
    tests/K7). Each stage is one `hal.dispatch(pso, args, Grid::Threads(count))` (`count = min(C,
    remaining)`, `EvalParams {count, first, domain, stride, quot[4]}` via `set_bytes`); the batch's serial
    encoder orders the stages and the next chunk's reuse of scratch/carry. 16 chunks × 58 stages = 928
    dispatches at po2 17 (the HAL commits a batch every 2048). The phase ends with `try_sync` (error →
    panic with the command-buffer error; `CircuitHal::eval_check` returns `()`).
  - Scratch (`EVAL_SCRATCH_ELEMS` = 8237 words a cycle) and carry (20 words a cycle) are
    `StorageModePrivate` (`hal.alloc_private`), stride = chunk, **cached** in the circuit HAL
    (`RefCell<Option<EvalScratch>>`) across calls and proofs; regrown only if a call needs a larger
    stride (a smaller domain/chunk reuses the larger buffers: `count <= stride`). Stride is
    `min(chunk, domain)`, so small proofs take small scratch (po2 12: 516 MiB, po2 ≥ 13: 1032 MiB).
    `release_eval_scratch()` frees them, `eval_scratch_bytes()` reports them.
  - Budget-aware chunk: if `allocated_size + scratch` exceeds `MetalHal::working_set_limit()`
    (`RISC0_METAL_MAX_WORKING_SET_BYTES` or `recommendedMaxWorkingSetSize`), it trims the pool and
    halves the chunk down to 1024 (warns); if even that does not fit, `alloc_private` panics with the
    HAL's budget message. No core count or RAM fraction is assumed.
  - `quot[cycle & 3]`: `vanishing_quotients(po2)` computes the four `1/((3·rou^k)^(2^po2) − 1)` on the
    host (as Intel; asserts rou's order) and passes them as raw Montgomery words
    (`BabyBearElem::as_u32_montgomery`), which the last stage reads with `Fp::fromRaw`.
  - `poly_mix`: `map_pow(poly_mix, POLY_MIX_POWERS)` (2175 FpExt, 34.8 KB) copied into a pooled shared
    buffer bound at `EVAL_BUF_POLY_MIX` (asserted equal to `EVAL_NUM_POLY_MIX_POWS`).
  - Asserts (K3's list): `(EVAL_MAX_COLUMN + 1) * domain <= 2^32` (po2 ≤ 19), `stride <=
    EVAL_MAX_STRIDE`, `EVAL_SCRATCH_ELEMS * stride` and `EVAL_CARRY_WORDS * stride <= 2^32`,
    `count <= stride`, `steps == 2^po2`, `INV_RATE` matches, and — because the kernels read without
    bounds checks — `check.size() == 4·domain`, ctrl/data/accum ≥ `TAPSET.group_size(g)·domain`,
    mix/out ≥ `MIX_SIZE`/`OUTPUT_SIZE`; plus "no stages" (skip build).
- `hal/metal/mod.rs`: `mod eval_check;`, an `eval: EvalCheckState` field, and `eval_check` now calls
  `eval_check_metal` (K2's CPU `poly_fp` bridge removed; the `#[cfg(test)]` `METAL_EVAL_CHECKS` count
  and `mark_phase(EvalCheck/Finalize)` calls kept). Unused imports removed; docs updated.
- `keccak-sys/src/lib.rs`: `pub mod metal_eval { include!(env!("KECCAK_METAL_EVAL_RS")); }`;
  `METAL_KERNEL_NAMES` is now `["scatter_preflight"]` followed by `metal_eval::EVAL_STAGE_NAMES`, built at
  compile time by a `const fn concat_names` (hand-written names stay in `METAL_HAND_KERNEL_NAMES`; K6
  appends its names there). One library load builds all PSOs.
- **Deviation (files outside the owned list)**: `RISC0_SKIP_BUILD_KERNELS` cannot be handled in
  `lib.rs` alone (`include!` needs the env var at compile time and build.rs did not set it under skip).
  `keccak-sys/build_metal_eval.rs` gained `write_skip_consts(out_dir)` (a stub
  `keccak_metal_eval.rs`: 0 stages, sizes 1, same bindings) and `keccak-sys/build.rs`
  `build_metal_kernels` calls it in a new 2-line `else` branch of its existing skip check. Merge note:
  K6 also edits build.rs (different lines).

## Assumed / not verified / gaps
- Stage counts other than 58 are build-time (`RISC0_KECCAK_METAL_EVAL_STAGES`); each was run in a
  separate target dir; the committed default stays 58.
- PSO/GPU times are indicative (load 22-120 from other agents). The first 16-stage profile run was
  killed after ~20 min (the watcher that launched it expired), so the reported 16-stage cold total may
  include some stages already cached by that run.
- Not measured: CPU eval_check time at po2 17 for a speedup ratio (K7); TG size 128 vs 256; chunk sweep.
- `eval_check_matches_cpu_po2_17` needs ~7 GB host RAM (CPU + Metal copies): ignored by default.
- `metal_peak_memory` samples every 100 µs plus phase marks (K2's method).
- Scratch is cached for the circuit HAL's lifetime (plan); a long-lived worker holding a keccak prover
  keeps ~1 GB of private memory between jobs unless it calls `release_eval_scratch()`.
