# G5: NTT v1 for BN254 Fr (Metal Groth16 prover)

Branch `metal/G5`, based on `zkminer/metal` (`5adc24fcf`). Scope: PLAN.md 4.5 row G5 (kernels
table rows `bit_reverse`, `ntt_stage`, `ntt_fused_stages`).

## What was ported / written

- `risc0/groth16-sys/kernels/metal/bit_rev.metal`: `bit_reverse` (in-place swap, thread i swaps
  with rev(i) when i < rev(i)); port of the Intel prover's `NttPlan::bit_reverse`
  (`kernels/intel/groth16_intel.hpp` lines 407-418).
- `risc0/groth16-sys/kernels/metal/ntt.metal`:
  - `ntt_stage`: one radix-2 butterfly level (Intel `NttPlan::stages`, lines 420-439),
    generalised to DIT and DIF, forward and inverse.
  - `ntt_fused_stages`: up to 9 consecutive levels in threadgroup memory (512 Fr = 16 KB),
    over 2^cols adjacent columns so later passes (q0 >= 9) load 2^cols contiguous Fr.
    Host asserts threadgroup bytes <= 32768 and threads <= the PSO maximum.
  - `ntt_powers` (out[j] = c * base^j from 32 squarings; Intel `powers()`, lines 365-383),
    `ntt_mul_powers` (x[i] *= shift^k with k = i or rev(i), two windows lo 2^12 / hi; the CUDA
    `LDE_distribute_powers` + `generate_partial_twiddles` idea), `ntt_scale` (x *= 1/n).
  - One twiddle table (w^j, j < n/2) serves both directions: w^-jj = -tw[n/2 - jj]; the sign
    is folded into the butterfly.
- `risc0/groth16-sys/src/metal/ntt.rs` (+ `pub mod ntt;` in `src/metal/mod.rs`): `NttKernels`,
  `NttSchedule { Radix2, Fused { cols } }` (default `Fused { cols: 2 }`), `NttPlan` with
  encode-only methods on the caller's compute encoder:
  - `encode_forward` / `encode_inverse` (natural order in and out; inverse scaled by 1/n),
  - `encode_coset_forward` (coefficients -> evaluations on shift * H),
  - `encode_to_coset` = the CUDA prover's `NTT_sequence` (`kernels/cuda/groth16_prover.cuh`
    lines 527-541): DIF inverse natural -> bit-reversed, multiply by shift^k / n in bit-reversed
    position, DIT forward bit-reversed -> natural; no bit-reversal pass.
  - Roots from ark-ff (`FftField::get_root_of_unity`), shift = primitive 2^(lg+1)-th root
    (CUDA `forward_roots_of_unity[lg_domain_size + 1]`, line 599); 1/n from ark. Tables expanded
    on the GPU into `StorageModePrivate` buffers at plan creation (one synchronous command buffer).
  - `fr_to_words`/`fr_from_words` (ark Montgomery limbs <-> 8 x u32 GPU layout; same bytes,
    R = 2^256), `submit_and_wait` (commit, wait, status check, GPU seconds), `buf::*` indices.

## Deviation: no MetalHal

`risc0-groth16-sys` does not depend on `risc0-zkp` (only `risc0-sys`), and Cargo.toml is not
owned by G5 (plan 9.2), so the NTT is written against raw metal-rs 0.29 (`DeviceRef`,
`CommandQueueRef`, `LibraryRef`, `ComputeCommandEncoderRef`), as G2's tests are. The API is
encode-only so G7 can put the NTTs of a, b, c and the coefficient-wise kernels in one command
buffer.

- `roots_match_sppark_tables`: ark forward roots, inverse roots and 1/n for lg 0..=28 equal the
  sppark tables (`kernels/intel/ntt_params.hpp`, parsed at test time) word for word, so the coset
  matches the one the proving key's H points were computed for.
- `tables_match_ark`: GPU twiddle table vs ark powers (lg 1, 5, 10, 13), shift.
- `ntt_lg10`, `ntt_lg16`: schedules Radix2, Fused{0}, Fused{2}, Fused{5}; forward == `fft`,
  inverse == `ifft`, inverse(forward) == input, coset_forward == `coset.fft`, to_coset(fft(p))
  == `coset.fft(p)`.
- `ntt_lg23`: the same five checks for the default schedule and Radix2.
- `ntt_small_sizes`: lg 0..=14 and 19, all four schedules (edge passes: lg < 9, partial last
  pass, cols clamped by q0).
- `ntt_offsets_and_batching`: two transforms at different buffer offsets plus an inverse in one
  command buffer.

## Measurements (indicative; other agents share the GPU)

M5 Max (40 GPU cores), command-buffer GPU time, single run in `ntt_lg23`:

| lg 23 | forward | inverse | coset_forward | to_coset (CUDA NTT_sequence) |
|---|---|---|---|---|
| Fused { cols: 2 } (default) | 23.2 ms | 24.5 ms | 26.0 ms | 42.2 ms |
| Radix2 | 38.3 ms | 39.7 ms | 40.6 ms | 71.8 ms |

Schedule sweep (`ntt_bench_schedules`, best of 5, forward / to_coset): Radix2 36.9 / 71.0;
Fused cols 0: 22.7 / 42.4, 1: 22.6 / 42.2, 2: 22.6 / 42.1, 3: 23.1 / 43.1, 4: 22.8 / 42.6,
5: 23.3 / 43.6, 6: 23.6 / 44.1, 7: 24.8 / 46.1, 8: 32.5 / 62.2 ms. The fused forms are within
noise of each other for cols <= 4: the transform is close to Fr-mul bound (23 levels x 2^22
butterflies = 96 M muls; G2 measured 5.6 Gmul/s, i.e. ~17 ms), not memory bound, at this size on
this GPU. A 3 x to_coset (prover's a, b, c) is therefore ~130 ms here; scale roughly by core
count (40 / 10) for a base chip (not measured).

**Peak GPU memory at lg 23** (`device.current_allocated_size()` delta with plan + one data
buffer alive): **384.5 MiB** = tables 128.2 MiB (twiddles 2^22 x 32 B = 128 MiB, coset
windows 2 x 4096 + 2 x 2048 Fr) + data 256 MiB. No scratch: every transform is in place. The
prover (3 polys) needs 768 MiB data + 128 MiB tables at lg 23.

Plan creation (tables on the GPU) and PSO creation are not separately timed; the whole lg 23
test is dominated by the ark-poly reference (~7-8 s CPU).

## Assumed / not verified

- Ordering of dependent dispatches inside one compute encoder relies on the default serial
  dispatch type + tracked buffers (plan 2.6); the multi-dispatch tests pass, but this was not
  separately probed.
- Behaviour under a 4 GB / 8 GB working-set budget (`RISC0_METAL_MAX_WORKING_SET_BYTES`) was not
  run (the knob belongs to F0/Z6's `MetalHal`, which this crate does not use); the footprint
  above is well under either budget.
- Base-chip timings: not measured (no such machine).

## Known gaps / issues for later items

- G7: build one `NttPlan` per proving key (lg = log2 of H size) next to the PSOs; call
  `encode_to_coset` on a, b, c in the same encoder as `coeff_wise_mul`/`_and_sub` (G4). The shift
  matches the CUDA prover (test `roots_match_sppark_tables`). `NttPlan` owns its own
  `NttKernels` (6 PSOs); G7 may want to share one library/PSO set.
- G9 (NTT v2): the twiddle table could shrink 2x-4x (windowed twiddles or per-level tables,
  trading a mul) which matters more than speed on 16 GB machines; fuse the coset multiply into
  the first DIT pass and the last DIF pass (saves one read+write of the vector, ~3 ms of 42);
  try a 1024-Fr (32 KB) block and register-level radix-4/8 butterflies; measure on fewer cores.
- `kernels/metal/README.md` (G1's) is unchanged; nothing in it is wrong for these files.
