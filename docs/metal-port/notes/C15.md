## 2. #17: the regrouped split (kept)

`kernels/cuda/ec_regroup_metal.py` (new) runs `eval_check_split.py`'s own generator. It applies
five pinned text hooks, and each hook must apply exactly once. Two things are Metal-only:
- `FORCE_SPLIT = (x1101, x12357)`: the one big leaf in each of parts 0 and 5 is split into its
  terms.
- `GROUPS`: an explicit packing of the 115 leaves into 14 parts.

The CUDA/HIP sources are not changed.

`cuda2metal_eval.py --split-rg` sends the result through the same path as `--split-lz`: branch
selection, rules, round trip, lazy Fp `lz2` and uint4 mix loads. The kernels are renamed
`ec_rg_part_0..13`, and `build.rs` passes `--split-rg`. Each part re-applies the gate/mix factors
of the tree nodes it touches and adds the previous parts' running sum. Only the association of
field additions changes, so the results are bit-identical (tested below).

Pins:
- `ec_regroup_metal.py --check` (run by `cuda2metal_eval.py --check --split --split-lz --split-rg`)
  requires that the hooked generator, with no override, reproduces `eval_check_split.cu` byte for
  byte.
- It also pins the regrouped shape (`EXPECT`, `PART_OPS`).
- The translator pins RG and RG-lz counts.

Per-thread stack after the change: every `ec_rg_part` is <= 1104 B. Parts 4, 5, 9, 11 and 12
have no stack (`agx_size.txt`).

**Kernel A/B.** Run in-process with C12's method: arms rotated each round, 15 rounds, po2 18, and
every arm's output asserted equal to the CPU eval_check. Arms `lz,rg,lz,rg`:

| arm | GPU ms median [min, max] |
|---|---|
| lz [0] | 44.26 [43.41, 45.07] |
| rg [1] | 27.77 [27.68, 28.10] |
| lz [2] (A-vs-A) | 44.21 [43.48, 44.49] |
| rg [3] | 27.74 [27.65, 28.07] |

- rg - lz: -16.47 ms [-17.18, -15.33], faster in 15/15 rounds.
- A-vs-A (lz[2] - lz[0]): -0.11 ms [-0.95, +0.91].

**Per-proof A/B.** `c15_ab_eval_in_process`: 11 C11 captures (10 poseidon2 and 1 poseidon_254
lift/join/resolve, all po2 18), one cached prover per suite, ABBA order per capture, 8 rounds after
a warm round (`ab_caps.log`, load average 3-6):
- round sums: A (lz) median 2248.8 ms [2231.3, 5760.0], B (rg) median 2059.9 ms [2042.8, 14838.1];
- B faster in 7/8 rounds;
- per proof, B-A median -16.99 ms;
- eval_check phase: 44.98 -> 27.92 ms.

Round 1 was slow in both arms (5.8 s and 14.8 s). The cause is unknown; it is the only outlier, and
all other rounds are within 1 %.

**Budgets.** Same harness, 7 rounds each:

|---|---|---|---|---|---|

**Memory.** No buffer changes. The process peak footprint of the A/B test is 5,481 MB at the
default, 4 GiB and 8 GiB budgets, both arms in one process.

**Cold start.** With `MTL_SHADER_CACHE_SIZE=0` (`c15_pso_times`, `pso.log`), building the 14 rg

## 3. R20 follow-on: function-constant domain specialization (NO-GO)

Go/no-go first, as the brief requires, using an upper bound. The built
`eval_check_split_rg.metal` was compiled twice offline with the build's flags (`fc/`):
- `rg_plain`: unchanged;
- `rg_const`: `params.po2, params.domain` replaced by the literals `18u, 1048576u`. A function
  constant can fold no more than a literal does.

Both metallibs went through `c15_eval_kernel_bench` (`lib=` arms; `kb_fc.log`, 15 rounds):

| arm | GPU ms median [min, max] |
|---|---|
| lib=rg_plain | 27.79 [27.75, 27.96] |
| lib=rg_const | 28.03 [28.00, 28.11] |
| rg (built-in) | 27.65 [27.62, 27.76] |
| lib=rg_const | 28.06 [27.97, 28.11] |

- const - plain: +0.23 ms and +0.26 ms (0/15 rounds faster).
- built-in vs offline plain: -0.14 ms.

Constant folding the domain makes the regrouped kernels slightly slower. They are no longer in
R18/R20's regime: their stacks are small and the `& mask` index arithmetic is not the bottleneck.
**NO-GO; nothing implemented.**

## 4. #27 step kernels (ablation only)

The brief says to ablate first. From the per-proof profile in section 1, the step kernels' share
of a ~190 ms proof is:
- witgen exec: 2-4 ms;
- witgen verify: 0.4-1.7 ms;
- accum: 4-10 ms.

That is 7-15 ms in all, 4-8 %. Even halving every step kernel would save 3-7 ms per proof, under
half of #17's gain. The larger sorted-witness work (sort 3-6.5 ms) is host/zkp code that C15 does
not own. **Not attempted in this item;** the numbers are recorded for a later wave. `pre_accum`
(~34 ms, the data commit) is now the largest recursion phase after eval_check.

## 6. Knobs

- `RISC0_METAL_REC_EC_REGROUP=0` reverts to the C13 default `lz`.
- `RISC0_METAL_REC_KERNELS=rg|lz|lz32|split|monolith` selects the variant explicitly.
- `RISC0_METAL_REC_LZ_UINT4=0` still reverts to the four-load form, which exists only for the
  6-part split.
