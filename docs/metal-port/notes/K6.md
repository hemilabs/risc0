## What was ported, from where
- **Source**: `keccak-sys/kernels/cuda/steps_{0..15}.cu` (54 `__device__` functions, 34,712 code lines,
  declared in `steps.cuh`), the runtime of `kernels/cuda/witgen.h` + `buffers.h`, and `nextStep` /
  `par_stepExec` of `kernels/cuda/ffi.cu:118-133`. CPU oracle: `kernels/cxx/ffi.cpp` (`stepExec`, parallel
  mode) via `generate_witness_host` / `host_witness`.
- **`keccak-sys/kernels/metal/witgen.h`** (new): `ExecContext` (cycle, current preimage, preimages, a
  thread-local fault word), `MutableBuf`/`GlobalBuf` as by-value structs replacing CUDA's virtual
  `BufferObj`s, `get`/`set`/`setGlobal` = `Buffer::get/set` semantics (back > cycle reads 0;
  "Inconsistent set" → `WITGEN_FAULT_INCONSISTENT_SET` and no write, as the CPU throws before writing;
  "Read of unset value" → `WITGEN_FAULT_UNSET_READ`), builtins `isz`, `inv_0`, `bitAnd`, `to_size_t`,
  externs `getCycle`/`getPreimage`/`nextPreimage` (preimages read as 32-bit words, no 64-bit math;
  out-of-range preimage → `WITGEN_FAULT_BAD_PREIMAGE` instead of CUDA's OOB read), `WitgenParams`
  (32 B, static_assert) and the kernel macro `R0_KECCAK_WITGEN_KERNEL(NAME, TOP)` (thread t runs run slot
  `base + t`; slot cycle/preimage range-checked → `WITGEN_FAULT_BAD_SLOT`; fault ORed once per thread).
  `[[max_total_threads_per_threadgroup(256)]]` precedes `kernel void`. Every literal is `Val(n)`.
  Step functions are `static __attribute__((noinline))` by default (`-DR0_KECCAK_WITGEN_INLINE` to let
  the compiler inline) — see the PSO measurements.
- **`keccak-sys/build_metal_witgen.rs`** (new, `#[path]` module of build.rs; build.rs gets the `mod` line
  and one call in `build_metal_kernels`): parses every `steps_<n>.cu` (signature, body), checks every
  token against a whitelist (builtins, `xN` locals declared once and before use, the function's own
  parameters, `step_Top_N` calls with arguments matching the callee's MutableBuf/GlobalBuf kinds,
  u32 literals, `( ) , ; = + - * { }`), every column literal against `kRegCountData` (1096) /
  `kRegCountGlobal` (17) from `defs.cu.inc`, `get`/`set` only on MutableBuf and `setGlobal` only on
  GlobalBuf, `getPreimage` index < 100, `steps.cuh` declarations == definitions, every function reachable
  from `step_Top`. Rewrites: signature → `R0_KECCAK_WITGEN_FN void f(thread ExecContext& ctx, ...)` in
  `namespace keccak_witgen`; `INVOKE_EXTERN(ctx, name` → `extern_name(ctx`; comment lines dropped.
  `step_Top`'s structure is verified (prologue cols 932..934, `step_Top_0`/`step_Top_24` blocks, then 12
  arm blocks whose condition is the one-hot column `j` read back right after it was set); the arm for
  cycle type `j` is derived from that read, not hard-coded. Output, per arm K ∈ {25..33, 50, 51, 52}:
  `$OUT_DIR/metal/witgen_arm_<K>.metal` = forward declarations + the functions reachable from
  {`step_Top_0`, `step_Top_24`, `step_Top_K`} + `step_Top_arm_K` (step_Top with every other arm's call
  replaced by `ctx.fault |= WITGEN_FAULT_WRONG_ARM;`) + kernel `step_arm_K`. Also
  `$OUT_DIR/keccak_metal_witgen.rs` (`WITGEN_ARM_KERNELS` by cycle type, `WITGEN_KERNEL_NAMES`,
  `WITGEN_BUF_*` bindings, `WITGEN_PARAMS_SIZE`, `WITGEN_FAULT_*` parsed from witgen.h,
  `WITGEN_FAULTS`, register counts; `KECCAK_METAL_WITGEN_RS`, written even under
  `RISC0_SKIP_BUILD_KERNELS`, when no sources are returned) and the probe
  `$OUT_DIR/witgen_probe/witgen_whole_tree.metal` (not in the metallib). Stale `witgen_arm_*.metal` are
  removed; files are written only when changed.
- **`keccak-sys/src/lib.rs`** (appended): `pub mod metal_witgen { include!(env!("KECCAK_METAL_WITGEN_RS")); }`.
  `METAL_KERNEL_NAMES` is untouched (K4 owns it); the witgen PSOs are built from `METAL_LIB` by name.
- **`keccak/src/prove/hal/metal/witgen.rs`**:
  - `MetalPreflightOrder` (`Key = (cycle_type, sub_type)`, as `CudaPreflightOrder`), now the Metal
    prover's `PreferredPreflightOrder`; `HOST_WITNESS = false` (the prover makes its own witness).
  - `run_buckets(preflight)`: the control word of each cycle is read from the preflight's scatter
    (`control_state` info, 4×8 bits), cycles grouped by (cycle_type, sub_type) stably — identity for
    `MetalPreflightOrder`, correct for any order (the test also runs `ForwardPreflightOrder`). 15 buckets.
  - `generate_witness_gpu`: shape/32-bit asserts, run_order + preimage_idx + preimages (u32 words)
    uploaded once, one dispatch per bucket with `WITGEN_ARM_KERNELS[cycle_type]` (`Grid::Threads`,
    `set_bytes` params), all in one batch, `try_sync`, fault word → `Err("keccak witgen (Metal): fault
    0x.. (INCONSISTENT_SET | ...)")`.
  - PSOs: `static OnceLock` per process (device registry id asserted), the 12 arms created concurrently
    on scoped threads; `warm_witgen_pipelines(device)` exposed for a startup warmup (not yet called).
  - `generate_witness`: parallel mode → GPU when `RISC0_KECCAK_METAL_WITGEN` is `gpu`, or `auto`/unset
    and po2 ≥ `GPU_WITGEN_MIN_PO2` (13); otherwise (smaller po2, `host`, sequential modes — fwd/rev not
    ported, plan 4.4) the CPU witgen over the shared buffers. **Fix found on the way**: the CPU witgen
    (`kernels/cxx/ffi.cpp`) indexes `preimage_idxs` by cycle, so it is only correct for a forward-ordered
    preflight; the host fallback now rebuilds the arrays in cycle order and calls
    `risc0_circuit_keccak_cpu_witgen` directly (`generate_witness_host` would have mis-indexed the
    `MetalPreflightOrder` preflight).
- **`hal/metal/mod.rs`** (not append-only, two small edits, flagged for the merge): the module-doc bullet
  on `generate_witness`, and `metal_prover_runs_on_metal_hal` now asserts `prove_host_witness` returns
  `None` (it asserted `Some` under K2's `HOST_WITNESS = true`).
- **Consumer of the host witness (correction, fix round 1)**: an earlier version of this note said no
  consumer of `prove_host_witness` exists. That was wrong. `risc0/zkvm/src/host/server/prove/prover_impl.rs`
  (~1226-1250, M3's widening) starts a CPU thread under `cfg!(any(feature = "intel", feature = "rocm",
  feature = "metal"))` whenever a session has more than one pending keccak; it calls
  `risc0_circuit_keccak::prove::host_witness` a proof ahead and hands each witness through
  `mpsc::sync_channel(1)` to `keccak.rs:47` (`prove_keccak_with` -> `prover.prove_host_witness`). With
  `HOST_WITNESS = false` the Metal prover returns `None`, so the witness is dropped and the keccak is
  proved again from its inputs (GPU witgen). The result is still correct, but every keccak now also pays a
  full CPU witgen for nothing, and the witnesses hold host memory: one witness is `2^po2 x 1096 x 4 B`
  (data) — about 1.15 GB at po2 18 (288 MB at po2 16) — and with `sync_channel(1)` up to two (one queued,
  one being built; briefly a third being dropped) are alive at once, i.e. ~2.3 GB of unified memory at
  po2 18 next to the ~7 GB GPU peak. That works against PLAN 9.1 (16 GB minimum target).
  `prover_impl.rs` is not a K6-owned file, so K6 does not change it; the one-line fix is handed to the
  zkvm/M3 owner or the merge agent (see "Issues for later items").
- Drop: still not needed (no process state; static PSOs live for the process like the zkp ones).

## Assumed / not verified / gaps
- e2e keccak proofs po2 14..18 were proved and verified with the GPU witness through `metal_peak_memory`
  (seals verify with `KeccakProver::verify`); verification against `KECCAK_CONTROL_IDS` through the zkr
  lift and the zk-miner KeccakAudit path were **not run** (unit acceptance, K8/M).
- Parallel correctness relies, as on CUDA and the CPU, on every back-row read hitting a scattered cell
  (cols 0..931); bit-exactness at po2 8..18 with two run orders is the evidence, not a proof.
- The crossover (po2 13), TG size (256), one dispatch per (cycle_type, sub_type) and noinline-by-default
  were chosen on the M5 Max only (40 cores); 8–10-core GPUs will move the crossover up.
- The OS shader cache is not a reliable warm path (above); PSO creation is lazy on the first GPU witness
  of a process (17–35 s cold with noinline, 200 s with inlining) — not yet in any warmup.
