# G3: zkey/SRS, coefficient and fuzzed-results loaders for the Metal Groth16 prover

Branch `metal/G3`, based on `zkminer/metal` (`5adc24fcf`, G1 + G2 merged, ark deps added).
Scope: PLAN.md 4.5 row G3.

## What was ported

- `risc0/groth16-sys/src/metal/srs.rs` (new, `pub mod srs`):
  - zkey parsing ported from the CUDA `SRS` constructor (`kernels/cuda/groth16_srs.cuh`, the
    non-Windows mmap path, lines ~207-425) with the Intel `Srs` (`kernels/intel/groth16_intel.hpp`
    186-279) as second reference: magic `zkey`, 10 sections, sections 1..9 in ascending order and
    within the file, protocol 1, section 2 (moduli, num_vars, num_public, domain_size, VK points
    alpha_g1, beta_g1, beta_g2, gamma_g2, delta_g1, delta_g2), points A/B1/B2/C/H (sections 5-9).
  - Additions beyond CUDA: section 3 (IC points, `num_public + 1`) is parsed (CUDA skips it) so the
    whole arkworks VK can be compared; the field moduli in section 2 are checked to be BN254's;
    section 2 must be exactly 660 bytes; section 4's record count must match its size (records are
    not loaded); A/B1/B2 must have `num_vars` points, C `num_vars - num_public - 1`, H
    `domain_size` (a power of two, checked before the counts).
  - `read_zkey_header(path)` reads only the header/VK/section table (a few KB) — G7 can learn the
    witness length without loading the key. `Srs::load(&DeviceRef, path)` = header + one
    `StorageModeShared` buffer per point section, filled with parallel 16 MiB `pread`s (up to 8
    threads) straight into `contents()`; no host copy stays resident, no `MetalHal`, no lock (G1's
    contract for `metal_preload`).
  - Raw GPU-layout types `G1AffineRaw` (64 B), `G2AffineRaw` (128 B), `G1JacobianRaw` (96 B),
    `G2JacobianRaw` (192 B): 4 x u64 LE limbs, Montgomery form, Fp2 = (c0, c1), infinity = (0, 0)
    (affine) / Z = 0 (Jacobian). `to_ark()`/`from_ark()` reinterpret the limbs as arkworks'
    internal Montgomery representation (`Fp::new_unchecked`), rejecting non-canonical limbs.
  - `SharedBuf<T: Pod>`: read-only shared buffer (`as_buf()` to bind as `const device T*`,
    `as_slice()` host view, `byte_len()`). Allocation goes through a raw
    `newBufferWithLength:options:` with a nil check (as zkp's `Runtime::new_buffer_raw`) and checks
    `max_buffer_length` first. `LoadStats` (elapsed, bytes, device `currentAllocatedSize` before/after).
- `risc0/groth16-sys/src/metal/coeffs.rs` (new, `pub mod coeffs`):
  - `Coeffs::load` ported from CUDA `preprocessed_coeffs(gpu, file_path)` (non-Windows, non-compact
    path of `groth16_coeffs.cuh`) and Intel `Coeffs`: 4 x u64 header (count_a, count_b, ind_a,
    ind_b), `coeff_t` records (48 B: m, c, s, pad, Fr value), then A's and B's row-start indices.
    File size must equal the header's size exactly (as CUDA's `compact_load` requires; Intel only
    requires >=). Two shared buffers: `coeffs` (A then B) and `indices` (A's then B's);
    `b_offsets()` gives B's element offsets for binding.
  - `Coeffs::validate(witness_len, domain_size)` (new; CUDA has no equivalent): everything
    `witness_into_poly` relies on — indices from 0, strictly increasing, ending at the count; A's
    m = 0, B's m = 1; one `c` per row, strictly increasing across rows, `< domain_size`; `s <
    witness_len`; values canonical Fr. Multi-threaded.
  - `FuzzedResults::load` ported from `groth16_prover::read_fuzzed_results_from_file`
    (`groth16_prover.cuh` 557-577) / Intel `read_fuzzed_results`: sppark `msm_results {point_t a,
    b_g1, c, h; point_fp2_t b_g2}`, 576 bytes, already negated. Requires exactly 576 bytes (CUDA:
    at least). `to_ark()` gives arkworks Jacobian points (arkworks' `Projective` is Jacobian).
- `risc0/groth16-sys/src/metal/mod.rs`: `pub mod coeffs;` and `pub mod srs;` only.
- `risc0/groth16/tests/metal_srs.rs` (new): the VK test. It is in risc0-groth16 because
  risc0-groth16-sys cannot depend on risc0-groth16 (cycle) and no Cargo.toml edit is allowed.

New tests:
- `srs::tests::raw_round_trip_and_canonical_check`: ark <-> raw round trip (64 random G1, G2),
  (0,0) -> identity, limbs of 1 are R mod p, limbs [1,0,0,0] are R^-1, modulus limbs rejected,
  Jacobian Z = 1 / Z = 0.
- `srs::tests::synthetic_zkey_loads`: a generated snarkjs-layout zkey (40 vars, 3 public, domain 16,
  random points, every 7th G1 / 5th G2 at infinity) loads with every point and the VK equal.
- `srs::tests::malformed_zkeys_are_rejected`: bad magic, 9 sections, out-of-order section,
  truncation, protocol 2, wrong Fq/Fr modulus, non-power-of-two domain, wrong point count, missing
  file — each with the expected message.
- `srs::tests::component_srs` (real zkey): 5,635,930 vars, 5 public, domain 2^23, 29,098,147
  coefficients; VK points on curve and in the subgroup, IC count, **e(beta_g1, G2) = e(G1, beta_g2)
  and same for delta** (ties G1 and G2 decodings together); 10,255 sampled points of A, B1, B2, C,
  H (2048 evenly spaced per section + both ends) canonical, on the curve and in the subgroup (436
  at infinity).
- `coeffs::tests::synthetic_coeffs_load_and_validate`, `malformed_coeffs_are_rejected` (header
  size mismatch, truncation, wrong m in A/B, mixed c in a row, non-increasing c, s out of range,
  non-canonical value, indices not from 0 / decreasing / not ending at the count),
  `fuzzed_results_layout` (generated 576-byte file decodes to the same ark points; 575 bytes
  rejected).
- `coeffs::tests::component_coeffs_and_fuzz` (real files): validates against the zkey sizes;
  `count_a + count_b` = zkey section 4 count, and **every A/B coefficient equals the zkey section-4
  record in file order** (m, c, s, value) — so the preprocessed file is exactly the zkey's
  coefficients split by matrix; fuzzed a, b_g1, c, b_g2 are non-zero, on the curve and in the
  subgroup.

probably partly warm; a truly cold read (purge needs sudo) was **not measured**.

## Assumed / not verified

- Cold-disk load time (no `purge` without sudo). Expect SSD-bound, roughly 1-3 GB/s on base
  Macs, so ~1.5-4 s for both files.
- Points are spot-checked, not all 28M checked on the curve (a full check costs seconds of CPU at
  every load); loads trust the file beyond the structural checks. Coefficients *are* fully
  validated by `validate` (cheap).
- The MSM vs fuzz identity (`MSM(P, f) + fuzzed == O`) is G7's (needs G4's ChaCha fuzz and G6's MSM).

## Issues for later items

- **G7: `fuzzed.h` is junk.** In the shipped `fuzzed_msm_results.bin` the `h` slot is not a curve
  point (CUDA never computes it; the setup wrote an uninitialised `point_t`; the test asserts it is
  off-curve). Never add it.
- **G7:** call `Coeffs::validate(srs.header.witness_len(), srs.header.domain_size)` after loading
  (10 ms) so kernels can index without per-thread clamps, or keep the clamps (plan 2.9).
  `Srs`/`Coeffs` are `Send + Sync` (metal `Buffer` is), so a mutex-guarded cache works; loaders
  take a `&DeviceRef` and no lock, as G1 requires for `metal_preload`.
- **G7/G10, memory on 16 GB Macs:** the loaded key is 3.78 GB of GPU memory, close to the whole
  ~4 GB minimum-tier budget (plan 9.1) before NTT/MSM scratch. The compact coefficients (CUDA cold
  path, 278 MB instead of 1.44 GB) and a zero-copy `newBufferWithBytesNoCopy` mmap of the zkey
  (G10) are the obvious levers; `release` must drop both `Srs` and `Coeffs`.
- C points: the C MSM's scalars start at `witness_len - c_len()` (CUDA `&d_fuzz[witness_size -
  c_size]`); `ZkeyHeader::c_len()` provides it.
