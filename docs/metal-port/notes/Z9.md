Branch `metal/Z9` (worktree `deps/risc0-wt-Z9`). This item started from a WIP commit left by an earlier
agent that hit a usage limit. I re-read that commit, kept what held up, fixed what did not, and re-ran
every gate and the key A/B tests myself.

Hardware: M5 Max, 40-core GPU, 36 GB. Other agents were using the GPU the whole time, with load averages
from 4 to 30 and GPU utilization often at 100%. Every A/B below is interleaved: A B / B A per pair, and
each pair waits until GPU utilization falls below 60% (capped at `Z9_IDLE_WAIT_S`). Where wall-time
medians are noise-dominated, the claim rests on per-dispatch GPU timestamps (the minimum over samples,
from the profiler added below) or on the per-variant minimum. Each table says which. Logs:

- **Allocation**: a fresh 1 GiB buffer + fill takes 86.6 ms; from the pool it takes 4.3 ms.
- **NTT passes** at lg 20 x 211: CT 270-400 GB/s, GS 227-577 GB/s, bitrev 275 GB/s. At lg 22 x 32: CT
  221-331, GS 264-498, bitrev 267 GB/s. Most passes therefore run at or near copy bandwidth.
- **Poseidon2**: Pv 358 Mperm/s (hash_rows 2^20 x 211 and fold 2^22). m32 349-351 Mperm/s.

## Kept changes (each one bit-exact, each with a revert knob)

### 1. Poseidon2 `_z9` reduction (default): 1.18-1.19x on hash_rows and the fold tree
`pv.metal`: a third instantiation `V = 2` (`pv_rows_k_z9`, `pv_fold_k_z9`, `pv_fold_tail_k_z9`) of the
thread-per-hash kernels.
- **How it works**: the product stays one 32x32 → 64 multiply, as in the HIP form. The Montgomery
  reduction is `hi(t) - mulhi(m, p)` (`sredc64h`) instead of the 64-bit multiply-add `t + m * -p`.
- **Why it is exact**: `t` and `m*p` agree in the low word, so the low word of `t - m*p` is zero and the
  high word is `hi(t) - hi(m*p)` with no borrow, mod 2^32. This is the same identity `sredc32` already
  relies on, and it holds for every `t`, not only within the lazy-reduction bounds.
- **Partial rounds**: the linear layer keeps the HIP int64 form, which the first agent measured faster
  there.
- **Inlining**: every pv/pvs helper is now `always_inline` (`PV_INLINE`). This also removes the R17
  tier B/C shapes from the TU (below). The first agent measured no speed change from it.

`RISC0_METAL_POSEIDON2=pv` restores the pre-Z9 kernels and `=m32` still selects the 32-bit form. The
`pvs` latency kernels are unchanged: `PvZ9` uses their `Pv` form.

### 2. mdiv (combos_divide): host loop below po2 16, E = 16 from po2 17
`mdiv.rs`:
- **Host loop below po2 16**: slices below `2^RISC0_METAL_MDIV_GPU_MIN_PO2` (default 16) run the
  existing host loop on the unified-memory buffer. `0` restores the pre-Z9 behaviour.
- **E = 16 from po2 17**: E = 16 is now used from po2 17 instead of 20.
  `RISC0_METAL_MDIV_E16_MIN_PO2=20` restores Z5's switch, and `RISC0_METAL_MDIV_E` still forces one E.

A/B results (`z9_mdiv_crossover`, the first agent's runs `mdiv_xo.txt` / `mdiv_xo2.txt`, 7 and 9 pairs,
load 4.6-12.8; wall time of the HAL call, median, and the ratio to GPU E8):

| po2 | GPU E8 | GPU E16 | host loop |
|---|---|---|---|
| 11 | 1.158 ms | | 0.201 ms (x5.8) |
| 12 | 1.212 ms | | 0.313 ms (x3.9) |
| 13 | 1.324 ms | | 0.458 ms (x2.9) |
| 14 | 1.366 ms | | 0.758 ms (x1.7) |
| 15 | 1.637 / 1.470 ms | | 1.425 / 1.439 ms (x1.14 / x1.02) |
| 16 | 2.113 / 2.094 ms | 1.976 ms (x1.07, ambiguous) | 2.71 ms (x0.78) |
| 17 | 3.234 ms | 2.927 ms (x1.12) | 5.22 ms |
| 18 | 5.526 ms | 4.719 ms (x1.18) | 10.4 ms |
| 19 | 4.720 ms | 4.085 ms (x1.21) | 22.4 ms |

What this means:
- **Below po2 15 the host wins outright.** Po2 15 is a tie, so the switch is at 16.
- **Where it matters**: this affects small segments and recursion only. At po2 20 nothing changes,
  because mdiv takes ~5 ms of GPU time per segment.
- **Core count (PLAN 9.1)**: on 8-20-core GPUs the GPU path is slower, so the true crossover can only
  move up. A default of 16 cannot select the GPU where the 40-core part loses. On a smaller chip it at
  worst keeps the pre-Z9 behaviour at po2 16-17.
- **Correctness**: `z9_mdiv_small_po2_gpu_equals_host` checks that the no-longer-default GPU shapes
  (po2 11-16, E 8 and 16) equal the host loop, in data and remainders. It also checks that the Hal
  default path gives the same result. Z5's suite still runs both paths. The revert-knob suite run
  (below) runs Z5's suite with the GPU at every size.

### 3. Measurement tooling (off by default)
- **Profiler**: `RISC0_METAL_PROFILE=1` (`runtime.rs`) commits every dispatch and blit in a command
  buffer of its own. It records `GPUEndTime - GPUStartTime` per kernel name (count, sum, and now the
  minimum, which is the least-disturbed sample on a shared GPU) and prints the table when a runtime
  drops. `profile_take` / `profile_report` are public. With the profiler off, the only cost is one
  `OnceLock` read per dispatch.
- **Threadgroup width**: `RISC0_METAL_THREADS_1D` sets the threadgroup width of `Grid::Threads`
  dispatches. The default stays 256, so behaviour is unchanged.
- **NTT step split**: `NttState::steps` lets a HAL override the NTT pass split. The override is set
  only through a `cfg(test)` hook, and the default is still sppark's split.
- **A/B harness**: `tests_z9.rs` holds the harness (`ab`, `wait_gpu_quiet`) and 10 `#[ignore]`
  measurements: `z9_microbench`, `z9_ab_poseidon2`, `z9_poseidon2_crossovers`, `z9_ntt_split_sweep`,
  `z9_ntt_commit_chunk_sweep`, `z9_ntt_commit_combo`, `z9_eu2_s_sweep`, `z9_mdiv_crossover`,
  `z9_threads_1d_sweep`, `z9_second_queue_overlap`. Knobs: `Z9_PAIRS`, `Z9_PO2`, `Z9_COLS`,
  `Z9_ROWS_LG`, `Z9_CHUNKS`, `Z9_SPLITS`, `Z9_IDLE_WAIT_S`, `Z9_IDLE_PCT`. Run them alone with
  `--release --ignored --nocapture`.

## What I changed on top of the WIP commit
- **Dead-code fix**: the WIP broke every non-test build of `risc0-zkp` (`deny(dead_code)`), because
  the bool-form `encode_fold/rows/fold_tail` and `form_of` were used only by Z3's tests. They are now
  `#[cfg(test)]`.
- **Kernel list**: the three `_z9` names moved to the end of `KERNEL_NAMES` (append-only list rule).
- **Profiler**: added the per-kernel minimum GPU time, which is what made the A/B readable on a
  saturated GPU.
- **Tests file**: a `Variant` type alias (clippy `type_complexity` in `tests_z9.rs`), and rustfmt.
- **Measurements**: re-measured Poseidon2 (GPU timestamps, at both budgets), the NTT split at commit
  level with an A-vs-A variant, and e2e twice. Ran every gate.

## Knobs (for the final baseline A/B)
- `RISC0_METAL_POSEIDON2=pv`: reverts change 1. `m32` selects the 32-bit A/B form.
- `RISC0_METAL_MDIV_GPU_MIN_PO2=0`: reverts the mdiv host crossover. `RISC0_METAL_MDIV_E16_MIN_PO2=20`
  reverts the E switch.
- `RISC0_METAL_PROFILE=1`: per-kernel GPU-time table (serializes the GPU work; measurement only).
- `RISC0_METAL_THREADS_1D=<n>`: `Grid::Threads` threadgroup width (default 256, unchanged).
