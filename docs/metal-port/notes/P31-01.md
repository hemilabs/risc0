## Follow-up commit `6cfa8b2b4` (needed for the CPU gates)

The merge commit alone does not pass the CPU gates, for reasons that are not merge resolutions:

1. **Pre-existing on M (wave 7):** a build without the metal feature fails under the workspace
   `-Dwarnings`.
   - `cargo check --workspace`: `PREWARM_GATE_ENV` in `recursion/src/prove/ctrl_persist.rs` is never
     used. W7-C1 added it, and only the metal-gated `gate_early_only` reads it.
   - lib test build: `set_test_mode`, `stats` and `clear` in the same file are never used. Only the
     Metal `c16_tests` call them.
   Fix: `cfg_attr(not(feature = "metal"), allow(dead_code))` on the constant, and
   `cfg(all(test, feature = "metal"))` on the three helpers.
2. **Pre-existing on R31:** the zkvm lib tests do not compile. `test_zkr` (`zkvm/src/host/recursion/prove/mod.rs:577`)
   passes `get_zkr(..)`, which returns `Program` on 3.1 (`49f42eb11`), to `Prover::new(Arc<Program>, ..)`.
   Fix: `.into()`, as hemilabs did in `zkr.rs` (`d36097fcb`).
3. Guest lockfiles: when cargo builds the guests, it rewrites the 11 R31 lockfiles and
   `povw/guests/log-builder/Cargo.lock`. It drops `metal` and its macOS deps (objc, block,
   core-graphics-types, foreign-types*, malloc_buf, bitflags 1.x, ...) because F2 gated the Metal
   dependency on target and feature. F2 committed the same re-resolution on 3.0. I committed the files
   cargo wrote, so a build leaves the tree clean.
