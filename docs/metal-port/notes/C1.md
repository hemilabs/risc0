### Kernels (source lines ported)

| Metal kernel | CUDA source | Notes |
|---|---|---|
| `injectWomBacks` | ffi.cu:728-752 (cxx/ffi.cpp:218-239) | Bindings data, womIndex, womRows, fault, `RecExecParams`. `idx > numWomRows` → fault + the zero row (plan 2.9); `Fp(0)` instead of `= 0`. Also returns for `cycle > totalCycles`. |
| `fillOneExt` | ffi.cu:1400-1405 | `FpExt(1u)`. |
| `prefixProductsChunks` / `Totals` / `Fixup` | ffi.cu:1303-1364 (SPPARK_NO_COOPERATIVE_LAUNCH path) + launch shape ffi.cu:1506-1541 | 1:1: 256 threads × 8 elements per 2048-element chunk, Hillis-Steele over a static `threadgroup FpExt part[256]` (4096 B; PSO reports `staticThreadgroupMemoryLength = 4096`), `[[max_total_threads_per_threadgroup(256)]]` before `kernel`. Indices are 32-bit (CUDA used `size_t`): valid for n ≤ 2^32 − 2048 (the host must check). Totals is a one-thread serial scan (as CUDA); Fixup dispatched over `n − 2048` threads only when nblocks > 1. Chunks must be dispatched as `Grid::Groups { ceil(n/2048), 256 }` exactly. |
| `recInitRows` / `recFillTail` / `recZeroizeRows` | ffi.cu:1792-1832 (launch shapes 1834-1873) | `uint4` stores through `device uint4*` (16-B aligned: base buffer + multiples of 4 words; needs logRows ≥ 2, host-checked like CUDA). `recZeroizeRows` uses a 2-D grid (`gid.x` row quad, `gid.y` column) instead of `blockIdx.y`; `select`/`any` instead of the four ternaries. All take `RecRowParams`. |
| `markHostChains` / `scatterHostChains` | ffi.cu:687-702 | Optional (round 1 does this on the CPU). Explicit buffers instead of `ExecContext*`; head/cycle indices clamped to numCycles (and totalCycles) with fault. |

Intel precedent consulted: `kernels/intel/accum.cpp` (blocked scan; same "associative and exact,
so bit-identical to the sequential scan" argument) and `kernels/cxx/ffi.cpp` (CPU
`injectWomBacks`, `sortWomFast`, used as the CPU reference shape).

Not in C1 (owned elsewhere): parStepExec/parStepVerifyWom/parStepComputeAccum/parStepVerifyAccum
wrappers (C2 translator), Perm/sort kernels (C11/C12), fwd/rev seq kernels (not ported).

## Test harness choice

recursion-sys has no `metal` or `risc0-zkp` dev-dependency and C1 may not edit Cargo.toml, so the
test drives Metal through a ~250-line `objc_msgSend` binding (Metal + Foundation frameworks,
`dispatch_data_create` for `newLibraryWithData`). It mirrors MetalHal's model (one command
buffer, one serial encoder per batch, `dispatchThreads` with min(256, PSO max) or
`dispatchThreadgroups`). C5+ will exercise the same kernels through `MetalHal::load_library`.

## Assumed / not verified / gaps

- The extern signatures and the `ExecCtx`/`AccumCtx` field names are C1's proposal for C2's translator; C2 may need small additions (e.g. a `steps` alias) — any change is to these two headers.
- The extern probe is compiled at run time with `MTLCompileOptions` (language 3.2, default fast-math) rather than offline `-O2`; the shipped kernels in `METAL_LIB` are the offline build.
- Prefix trio uses 32-bit indices (n ≤ 2^32 − 2048) and the HAL (C7) must size `totals` as ceil(n/2048) FpExt and skip Totals/Fixup when nblocks == 1, as the test does. A `simd_prefix`-style scan is a C11 optimization item.
- `recInitRows`/`recZeroizeRows` assume 16-byte aligned buffer bases (true for MTLBuffers at offset 0; a HAL that binds with a non-multiple-of-16 offset must not use them).
- Host-chain kernels are optional; round 1 does that work on the CPU.
