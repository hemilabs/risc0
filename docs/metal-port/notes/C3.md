## Translation (source lines -> output)

### Monolith (`eval_check.cu` -> `eval_check.metal`)

Input: `kernels/cuda/eval_check.cu` (12381 lines, zirgen output: `poly_fp` at :11-12379). Line
shapes (all compile unchanged except the rules below): 4679 `Fp x = x * x`, 4061 `+`, 1385 `-`,
1076 `FpExt x = x + poly_mix[k] * x`, 152 `x + x * x * poly_mix[k]`, 669 trace reads
`data|ctrl|accum[k * size + ((idx - INV_RATE * k) & mask)]`, 32 `out[k]`, 20 `mix[k]`, 284 consts.

The kernel (generated block) ports `ffi_supra.cu:43-68` (`eval_check`, non-HIP branch:
`pow(rou, cycle)`, `pow(Fp(3) * x, 1 << po2)`, `tot * inv(y - Fp(1))`, 4 column-major writes;
`ret[i]` -> `ret.elems[i]`; `__launch_bounds__(256, 1)` -> `[[max_total_threads_per_threadgroup(256)]]`).
`poly_mix` (CUDA `__constant__ FpExt poly_mix[158]` from `eval_check.cuh`, filled by
`cudaMemcpyToSymbolAsync`, ffi_supra.cu:95-104) becomes the first parameter of `poly_fp`
(`const device FpExt* poly_mix`) and buffer 0 of the kernel. `INV_RATE` (eval_check.cuh, `size_t`)
is defined in the prelude as `constant constexpr uint32_t INV_RATE = 4` (32-bit index math; the
index bits under `& mask` are identical because mask < 2^32).

### Split (`eval_check_split.cu` -> `eval_check_split.metal`, `--split`)

Input: `kernels/cuda/eval_check_split.cu` (28006 lines; eval_check_split.py + ec_lazyredc.py).
1. **CUDA branch selection**: every `#if/#ifdef/#elif/#else/#endif` (59 directives) is evaluated
   with `__HIPCC__`, `__HIP_DEVICE_COMPILE__`, `__GFX11__`, `__GFX12__`, `__gfx1201__` undefined;
   any other macro or operator in a condition is refused. 14164 HIP-only lines are dropped; what
   remains is exactly what nvcc compiles: the six `#else` `poly_fp_part<P>` bodies (lines
   4431-6539, 8239-11279, 13924-15556, 17665-19766, 23143-25094, 25103-27889), the RecLz lazy
   Montgomery helpers (:157-208), `poly_fp_part` (:27895), `ec_part_body<P>` (:27907-27928).
2. Rewrites (below), including `poly_mix` threaded as the first parameter through every
   `poly_fp_part*`, `rec_lz_add` (1060 call sites) and `ec_part_body`; `blockDim.x * blockIdx.x +
   threadIdx.x` -> a `gid` parameter (from `thread_position_in_grid`; Metal's
   `threads_per_threadgroup` differs in a non-uniform last group); `tot[i]` -> `tot.elems[i]`;
   RecLz word views get `thread`/`device` address spaces; `rou ^ cycle` uses
   `sppark_compat.h`'s `operator^`.
3. The CUDA template kernel `ec_part<P>` and the host code after it (launch_parts,
   eval_check_split, warm_parts, rec_eval_check_split_warmup: :27945-28006, 51 lines) are kept as
   `//c2m- ` comment lines (shown after the rewrites; never compiled).
4. Generated kernels `ec_part_0..5`, each `ec_part_body<P>(poly_mix, gid, ...)` (text-expanded
   instantiations, no `[[host_name]]` template kernels needed).

### Kernel ABI (both modes; for C8)

```
buffer(0) poly_mix const device FpExt*  158 FpExt (raw words as Rust's BabyBearExtElem)
buffer(1) check    device Fp*           4 * domain, column-major (as CUDA)
buffer(2) ctrl  (3) data  (4) accum  (5) mix  (6) out (= globals)   const device Fp*
buffer(7) params   constant RecEvalParams& { u32 rou (raw Montgomery word), po2, domain, _pad = 0 }  // 16 B
Grid::Threads(domain), threadgroup <= 256 (PSO max_total_threads = 256, static TG 0)
split: ec_part_0..5 in order on one serial encoder over the same bindings (part P > 0 reads
the sum part P-1 left in check; only part 5 applies the quotient)
```
`RecEvalParams` is defined in each file's generated prelude (no shared header). No fault buffer:
eval_check has no asserts and only `& mask`-clamped trace reads; the host must make
`domain` a power of two with every column buffer at least `cols * domain` long (C8).

## Measurements (M5 Max, shared with other agents: indicative only)

**Cold PSO creation** (`new_compute_pipeline_state_with_function`; fresh-content metallibs built
with `--define C3M_PSO_NONCE=101/102`, one mode per process):

| | nonce 101 | nonce 102 | in one process with the other mode (out3, 2 runs) |
|---|---|---|---|
| monolith `eval_check` | 20.2 s | 16.9 s | 43.0 / 39.7 s |
| split, sum of 6 parts | 7.0 s (1.46/1.14/0.76/0.65/1.44/1.54) | 6.2 s | 7.3 / 7.2 s |
| warm (OS shader cache hit) | 0.001 s | | |

The monolith matches the planners' 20.9 s when compiled alone; 35-43 s was seen when it compiled
next to other work. **Shader-cache observation**: the second process loading the same metallib
recompiled in full (6.6 s / 17.4 s for nonce 101; also out3 runs 1-3); only from the third load
on was it 0.001 s. So "instant on the second run" (plan 9.1 / C2's note) did not hold here;
consumer machines may pay the cold cost twice. This argues for an `MTLBinaryArchive` / explicit
warmup (C11, K5, M1).

**GPU time per call** (command buffer commit->complete, cold/warm call; po2 is the trace po2):

| po2 (domain) | monolith | split (6 parts) | CPU reference (poolstl par) |
|---|---|---|---|
| 12 (16384) | 4.8 ms | 3.0-3.6 ms | 26.5 ms |
| 16 (262144) | 35.3 ms warm | 16.0 ms | 293 ms |
| 18 (1048576) | 130 ms warm | 59.6 ms | 1145 ms |

Split is ~2.2x faster than the monolith at po2 16-18 on this GPU (register pressure of the 12k-line
monolith is the likely reason; not profiled). Not a decision: C11 owns monolith vs split.

**Peak GPU memory** (`current_allocated_size`): PSOs alone 1.2 MB (split) / 1.5 MB (monolith),
2.6 MB both. eval_check allocates nothing besides `check` (16 B x domain) and poly_mix (2.5 KB);
the harness peak at po2 18 was 655 MB, which is the trace inputs (163 columns x 2^20 x 4 B =
652 MB) + check 16 MB. At po2 16: 166 MB.

## Assumed / not verified / gaps

- Tested with random canonical field elements, not a real recursion trace; correctness rests on
  bit-exact agreement with the CPU `poly_fp` for random inputs (which exercises every term) and on
  fp.h/fpext.h (F1). The split's RecLz path assumes canonical inputs (`< P`), as on CUDA.
- `rou` in the harness is random, not a root of unity (the formula is the same either way).
- Cold PSO on 8-10-core base chips is not measured; the compile runs on the CPU, so expect it to
  scale with CPU speed, not GPU size.
- No GPU time is a gate; numbers above were taken while other agents used the machine.
- The `//c2m-` host-code comments show the rewritten spellings (`const device Fp*` inside CUDA host
  code), because the rules run before the commenting; harmless, noted for readers.
