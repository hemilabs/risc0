# G7: Metal Groth16 prover orchestration

Branch `metal/G7`, based on `zkminer/metal` (`a695b814b`, G1-G6 merged). Scope: PLAN.md 4.5 row G7,
errata 8.1 (`metal_proofs_verify`), 9.1 (budgets, peak memory).

## What was done

- **`groth16-sys/src/metal/prover.rs`** (new): `MetalProver`, a port of the Intel prover's
  `Prover` constructor and `Prover::prove` (`kernels/intel/groth16_intel.hpp` ~l.774-915), which
  follows the CUDA prover (`kernels/cuda/groth16_prover.cuh` `prove`, ~l.664-790):
  - construction: zkey header first (`srs::read_zkey_header`), **one budget check of the whole
    footprint** (points + coefficient file + a/b/c + witness + fuzz + window sums + NTT tables +
    `MsmScratch::bytes_for` + 32 MiB slack) before loading anything; then `Srs::load`,
    `Coeffs::load` + `Coeffs::validate(wn, n)` (G3's advice: kernels can trust indices),
    `FuzzedResults::load(..).to_ark()` (fuzzed.h never used, G3), the VK as ark points, buffers
    (a/b/c and fuzz `StorageModePrivate`; witness, fault word, window sums shared), `NttPlan` (G5),
    `MsmScratch` for max(wn, n) with c = 16 (G6), and the ChaCha fuzz (`chacha_fuzz`, all-zero key
    and nonce, `fuzz_blocks(wn)` blocks; G4). Checks A/B1/B2 = wn points, C <= wn, H = n (Intel).
  - `prove(witness_bytes)`: copy into the shared witness buffer, then **4 command buffers** on one
    queue, committed back to back and waited once: (1) blit zero a/b/c, `witness_into_poly` A and
    B, `fr_mul` c = a*b, `encode_to_coset` x3, `fr_mul_sub_from_mont` (h), `fr_add` w += f;
    (2) sort h + MSM H; (3) sort w + f + MSM A, B1, C (`first = wn - c.len`); (4) MSM B2 (G2).
    `RISC0_G16_METAL_PROFILE=1` gives every stage its own command buffer (finer GPU times).
    After the wait: fault word must be 0, command-buffer status checked, window sums combined on
    the host (`MsmCurve::combine_windows`), fuzz removed (+fuzzed results, already negated),
    blinding in ark exactly as Intel: A = A' + alpha + r delta1, B = B2' + beta2 + s delta2,
    B1 = B1' + beta1 + s delta1, C = C' + H + s A + r B1 - rs delta1. r, s: 64 bytes from
    `/dev/urandom` reduced mod r (groth16-sys has no `rand` dependency).
  - `Proof::proof_json` = Intel's `write_proof_file` format (decimal, pi_b pairs (c0, c1),
    `["1","0"]`); `public_json` = CUDA `write_public_file` shape with decimal strings
    (`witness[1..=num_public]`, checked canonical).
  - Pipelines: `kernels()` is a process-wide `OnceLock` (device, queue, library, `SmallKernels`,
    `MsmKernels`) and survives `metal_release`; only the NTT plan's 6 PSOs are rebuilt per key load.
  - `fuzz_check()` computes MSM(P, f) + fuzzed for A, B1, C, B2 (test hook).
- **`groth16-sys/src/metal/mod.rs`**: real entry points. `metal_supported()` returns Ok when a
  Metal device exists and the metallib is non-empty, else `MetalUnavailable` (renamed from G1's
  `MetalNotImplemented`; only groth16's metal.rs used it). `metal_preload` / `metal_prove` /
  `metal_prove_witness` (slice form, length checked) / `metal_release` / `metal_warmup` (builds the
  PSOs only, for M1) / `metal_is_loaded`, over a `Mutex<Option<MetalProver>>` cache (rebuilt if
  the setup paths change). `RISC0_METAL_MAX_WORKING_SET_BYTES` helpers: `parse_bytes` (Z6's
  grammar), `working_set_budget`, `working_set_limit` (= min(budget, recommendedMaxWorkingSetSize)),
  `check_working_set` (Z6's error text). The preload uses no `MetalHal` and no GPU lock (G1).
- **`groth16-sys/src/metal/msm.rs`** (G6's file, per the item text): `MsmScratch::new` now checks
  the budget for the whole scratch before allocating; `MsmScratch::bytes_for` (sizes factored into
  `sizes()`, values unchanged).
- **`groth16-sys/src/lib.rs`**: re-exports updated (`MetalUnavailable`, `metal_prove_witness`,
  `metal_warmup`).
- **`groth16/src/prove/metal.rs`** (G1's file): the GPU path now runs; Docker fallback only on
  `MetalUnavailable` or `RISC0_GROTH16_METAL_PROVER=docker` / `RISC0_METAL=0` /
  `RISC0_METAL_SKIP=groth16`; every other error (missing component, budget, GPU fault, bad seal)
  is returned. `gpu_prove(seal, pre_gpu, work_dir)` writes proof.json/public.json in a given dir
  (tests read them); the loader thread is joined before a witness error is returned; the witness
  is passed as a length-checked slice. Exclusive lock unchanged (held over loader join + prove).
  Tests updated (`gpu_selection` now expects the GPU on this Mac; `falls_back_to_docker` forces
  `MetalUnavailable` through an injected capability check; new `bad_seal_is_an_error`).
- **`groth16/src/prove/metal_tests.rs`** (new, errata 8.1): `metal_shrink_wrap` (3 GPU wraps,
  each verified by `Verifier::new(seal, control_root, claim_digest, bn254_control_id, vk)` and by
  `Verifier` over proof.json + public.json, public.json == reference, proofs pairwise different)
  and `metal_proofs_verify` (2 rounds of `prove::release_srs` + `prove::shrink_wrap` (cold key)
  + `prove::shrink_wrap_with` (cached), all verified). The **public.json reference** is the
  independent pipeline `to_json` (seal_to_json) -> `circom_witnesscalc::calc_witness` (the
  crate's own evaluator, not `fast.rs`) -> witness[1..=5].
- **Fixture** `groth16/tests/data/identity_p254_seal.{bin,json}` (new; 222,668 B seal + claim
  digest / control root / BN254 control id). Generated with a temporary, uncommitted zkvm test
  appended to `zkvm/src/host/server/prove/tests.rs`: `identity_p254(prove_nothing_succinct())`,
  `get_seal_bytes()`, `Groth16ReceiptVerifierParameters::default()`, `claim.digest()`; run with
  `cargo test -p risc0-zkvm --features metal --lib -- g7_dump_identity_p254_fixture --ignored`.

## Measurements (M5 Max 40-core, other agents' GPU/CPU work running, load average 46-56: indicative)

Per-stage GPU time, `RISC0_G16_METAL_PROFILE=1` (one command buffer per stage), wn = 5,635,930,
domain 2^23, three wraps:

| stage | ms |
|---|---|
| zero a/b/c + witness_into_poly A, B + c = a b | 78-265 (noisy; ~220 typical) |
| 3 x to_coset + h + w += f | 131 |
| sort h / MSM H (2^23 G1) | 43 / 355-361 |
| sort w / MSM A / MSM B1 / MSM C (G1, 5.6M) | 28 / 247-285 / 248-291 / 248-262 |
| MSM B2 (G2, 5.6M) | **1045-1253** |
| GPU sum | 2.47-2.90 s |
| host: upload 13-46 ms, combine + blinding 1.2-5 ms | |

Default mode (4 command buffers): GPU sum 2.45-2.82 s, prove 2.50-3.07 s. **Total wrap**
(`shrink_wrap`, key cached): 3.1-4.4 s = witness 0.66-1.43 s (CPU, `fast.rs`) + prove. Through
zkvm `succinct_to_groth16`: shrink_wrap 3.0-5.4 s. The plan's target of < 2 s is **not met**: the
G2 MSM alone is ~1.1 s and the four G1 MSMs ~1.1 s (G9). The first wrap of a process pays the
witness graph build (~10 s under this load).

Build (key load) with warm pipelines: srs 0.35 s, coeffs 0.21 s, validate 0.01 s, GPU setup
(NTT plan, scratch, fuzz) 0.04-0.30 s, total 0.6-1.0 s. A release + reprove costs that again.

**Cold pipeline creation is much worse than K3's figure**: `kernels()` (small + MSM PSOs) took
**355 s** in a fresh test binary under `MTL_DEBUG_LAYER=1`, and a first non-debug wrap in a
freshly built test binary took 343 s; warm it is 3-173 ms. Two zkvm wraps in the zkvm run took
226-267 s for the same reason (first use of the library in that binary). It seems the OS
shader cache does not carry over between differently-built executables; M1 must call
`risc0_groth16_sys::metal_warmup()` at worker start.

**Peak GPU memory** (device `currentAllocatedSize`, process-wide): the cached prover holds
**5628.7 MiB** (from ~5 MiB before: key points 2232 MiB + coefficients 1375 MiB + a/b/c 768 MiB
+ witness 172 MiB + fuzz 172 MiB + NTT tables 128 MiB + MSM scratch ~640 MiB + window sums). It is
allocated at construction and does not grow during a proof (prove allocates nothing; reported
`allocated` after every proof = 5628.7 MiB). Planned footprint (budget check) 5655.5 MiB. It
stays until `metal_release`/`prove::release_srs`.

## Assumed / not verified

- Docker was not run (not installed); the fallback path is G1's, now exercised through an
  injected `MetalUnavailable`.
- Base-chip timings not measured. Nothing depends on a core count; on a 16 GB machine the 5.6 GB
  footprint exceeds the ~4 GB active budget (clean refusal under a budget) and fits the idle one.
- Blinding randomness from `/dev/urandom` (CUDA/Intel use `std::random_device`, 31 bytes);
  uniformity of 64-byte reduction assumed adequate (standard).
- The fixture is one seal (multi_test DoNothing); other claims are covered by the zkvm tests.

## Known gaps / issues for later items

- **G9 (perf, measure first)**: MSM B2 is 40% of the GPU time (G6's 4.4x G2 gap); the four
  G1 MSMs ~1.1 s; `witness_into_poly` ~220 ms for 29M coefficients (serial rows; compact
  coefficients or a row-split). Sorting is cheap (28-43 ms).
- **G10 / 16 GB Macs**: 5.6 GB resident; levers: compact coefficients (-1.2 GB), zkey mmap
  no-copy, freeing a/b/c (768 MiB) after H by aliasing them with MSM scratch, `max_piece_bytes`.
- **M1**: call `metal_warmup()` at worker start (cold PSOs took minutes here); `release_srs`
  returns 5.6 GB; the pipelines stay.
- **fast.rs / to_json (not owned)**: `bytemuck::cast_slice::<u8, u32>` on the seal panics on an
  unaligned slice (the tests copy the fixture into a `Vec<u32>`); zkvm's seals are `Vec<u8>` from
  the allocator, so aligned in practice. G8 may switch to `pod_collect_to_vec`.
- `groth16/Cargo.toml`'s `metal` feature comment still calls the prover a stub (not owned).
- G8: review error/mutex paths (the cache mutex is held for a whole prove; a prestart preload
  waits behind it), proof-format parity with a CUDA/Docker proof of the same seal (no NVIDIA/Docker
  here), pre-blinding dump under `RISC0_VERBOSE`.
