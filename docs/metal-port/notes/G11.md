## Summary
- **The groth16 PSOs of the default path now load from an `MTLBinaryArchive`.** They go through the
  shared zkp module (`risc0_zkp::hal::metal::archive`, unit `groth16`). That module brings the key
  (metallib digest + device + OS build + names), the integrity check, keep-N cleanup and the fallback
  to a plain build. Its code is unchanged; only a doc line naming the new unit was added. No copy of
  it was made.
- **Worker cold startup (`MTL_SHADER_CACHE_SIZE=0`), 8 interleaved pairs:**
  - pipeline build: **31.8 s -> 10.0 s** (-21.3 s per pair, 0/8 slower);
  - process wall time for `BENCH_ONLY=fibonacci --benchmark`: **40.0 s -> 18.5 s**;
  - groth16 PSOs: **31.75 s -> 0.0 s**.

  Cold startup is now set by rv32im+zkp and recursion (~10 s each, in parallel), not by groth16.
- **Test-level cold A/B** (the production `kernels()` plus the 2^23 NTT plan), 8 rounds:
  - pre-G11 loader: **30.97 s** [26.38, 33.34];
  - archive hit: **0.049 s** [0.033, 0.112];
  - archive miss (empty directory, the first run on a machine): **28.91 s** [19.86, 32.23], which
    is -2.0 s per round, 0/8 slower. The miss builds the PSOs concurrently and compiles each once.
- **Warm start (OS shader cache warm): no change.** Per round: -2 ms [-39, +48], 3/9 slower. The
  archive costs ~2 ms (`kernels()` 0.020 -> 0.022 s; it reads and checksums a 4.2 MB file).
- **Kernel speed: no change.** The in-process interleaved A/B (plain vs archived PSOs, 9 pairs, 2^20
  MSM) gives a G2 MSM delta of +0.15 ms [-22.2, +1.0] (5/9 slower) and a sort+G1+G2 delta of -0.75 ms.
  Every MSM equals arkworks.
- **Memory:**
  - device allocation is unchanged: 3893.1 MiB, and the wrap peak at the 4 / 8 GiB budgets is the
    same;
  - process peak footprint is +3 MB (the archive file read).
- **Revert knob:** `RISC0_G16_METAL_ARCHIVE=0` restores the pre-G11 loader exactly. That loader
  builds the small and MSM PSOs serially in `kernels()` and builds the NTT PSOs with each plan. The
  shared `RISC0_METAL_ARCHIVE=0` and `RISC0_METAL_ARCHIVE_DIR` apply as well.
- **Correctness:**
  - no kernel changed;
  - the groth16-sys suite passes twice (59/0) and once with the knob off;
  - the risc0-groth16 suite passes twice (13/0) and once with the knob off. Every wrap is verified
    with `Verifier`, and public.json is checked against the reference;
  - every worker run proved, wrapped and verified (16 cold runs and 4 budget runs).

## Change: groth16 PSOs through the zkp binary archive
Code (all in `risc0/groth16-sys`):
- `src/metal/pipelines.rs` (new):
  - `ARCHIVE_ENV` (`RISC0_G16_METAL_ARCHIVE`) and `ARCHIVE_UNIT` (`groth16`).
  - The archived set: `SMALL_PSOS` (8), `MSM_PSOS` (10, the eager ones: sort plus `_g1w`/`_g2w`)
    and `NTT_PSOS` (9). That is 27 PSOs, and the list is part of the key.
  - `PsoSource`: `Plain` builds through the library; `Archived` takes the PSO from an
    `ArchivedKernels`, and a name outside the set is built plainly and counted.
  - `build_archived` (`ArchivedKernels::new_in(dir, device, "groth16", METAL_LIB, names)`) and
    `describe`.
- `SmallKernels`, `MsmKernels` and `NttKernels` each gain `from_source`. Their `new(device, lib)` is now
  `from_source(PsoSource::plain(..))`, with the same names in the same order.
  - `NttKernels` is `Clone` (retained references).
  - `NttPlan::with_kernels` builds a plan from given kernels, and `with_schedule` calls it.
- `prover::Kernels` gains `ntt: Option<NttKernels>` and `archive: Option<ArchiveReport>`, plus
  `Kernels::ntt_plan(lg)`.
  - With the archive on, `build_kernels` builds the 27 PSOs through the archive (concurrently on a
    miss), and every NTT plan clones the shared NTT kernels. A key load therefore compiles nothing,
    and `metal_warmup` now also covers the NTT PSOs.
  - `RISC0_VERBOSE` prints one `[groth16-metal] pipelines: ...` line.
  - With `RISC0_G16_METAL_ARCHIVE=0`, the pre-G11 body runs unchanged and `ntt` is `None`, so plans
    build their own PSOs.
- **The lazy revert pipelines stay lazy and plain.** The `_g1`/`_g2` MSM PSOs (G10; used only with
  `RISC0_G16_METAL_G9_OFF=wide_mul` or `RISC0_G16_METAL_EAGER_PSOS=1`) are not in the archive.
  Archiving them would add their compile to the miss run of every user for a path that is not the
  default. The 3 non-`_w` NTT PSOs (`ntt_stage`, `ntt_fused_stages`, `ntt_mul_powers`) are archived,
  because `fused_log` is sized from `ntt_fused_stages` as before; they cost ~0.1 s cold.
- `Cargo.toml`: `risc0-zkp` is an optional dependency under `metal` (`risc0-zkp/metal`). risc0-groth16
  already depends on it with `metal`, so the worker builds nothing new. There is no cycle: zkp does not
  depend on groth16-sys.
- `risc0/zkp/src/hal/metal/archive.rs`: one doc line adds `groth16` to the unit names, which are not
  `-`-prefixes of each other.
- `Cargo.lock`: `risc0-zkp` is added to risc0-groth16-sys's dependencies. zk-miner's lock gains the same
  edge on its next build (merge item).

Archive file: `~/Library/Caches/com.risczero.RISC-Zero.risc0/metal-archives/groth16-<key>-<sum>.binarchive`.
It is 4.2 MB, against 24 MB for rv32im and 35 MB for keccak.

## Tried and rejected / not done
- **Archiving the lazy `_g1`/`_g2` MSM PSOs:** not done (above). They compile only when the G9
  revert is used. `RISC0_G16_METAL_EAGER_PSOS=1` still builds them plainly.
- **A separate archive for the revert pipelines** (as keccak's `keccakstrict`): not needed. They are
  6 PSOs on a debug-only path, and G10 already keeps them off the default path.
- **Making the 3 non-`_w` NTT PSOs lazy:** rejected. `fused_log` uses both fused PSOs' thread limits,
  and keeping that rule unchanged is worth more than ~0.1 s on a miss run. On a hit run they cost
  nothing.
- **Splitting `msm_segment_reduce_g2w`** to shorten the first-ever (miss) compile, which takes ~25-29 s
  for that one kernel: out of scope (a kernel change, R17 audit). Open issue below.

## Knobs
- `RISC0_G16_METAL_ARCHIVE=0`: the pre-G11 loader, exactly (serial plain builds; NTT PSOs per plan).
- Shared: `RISC0_METAL_ARCHIVE=0` disables every unit's archive. Then groth16 still builds its PSOs
  once, concurrently, through the archive module's no-archive path. `RISC0_METAL_ARCHIVE_DIR` and
  `RISC0_METAL_ARCHIVE_KEEP` (keep-4 per unit) apply too.

## Core count, budgets (PLAN 9.1)
Nothing here depends on core count: the miss path uses the archive module's `available_parallelism`
threads. On 8-10-core parts the cold compile is longer, so the hit path saves more. The archive key
includes the device name and OS build, so a binary is never reused on another GPU or after an OS
update. GPU memory is unchanged.

## Open issues
- **Cold startup is now ~10 s, set by rv32im+zkp and recursion.** With the R14 archive hit, rv32im's
  own 13 PSOs load in 0.02 s, so the remaining ~10 s is the zkp HAL's PSOs (built plainly) and the
  recursion PSOs (C11: no archive). Routing both through the same archive module, under units such as
  `zkp` and `recursion`, would take a cold worker start to well under a second. Owners: zkp HAL and
  recursion (not G11's files).
- **The first-ever (miss) compile** of `msm_segment_reduce_g2w` is 25-29 s on the M5 Max (75 % of the
  groth16 cold cost). It is paid once per metallib, device and OS build. A smaller G2 reduce kernel, or
  splitting it, would shorten the first run on a new machine (a kernel item, with R17 rules).
- **Merge:** zk-miner's `Cargo.lock` gains `risc0-zkp` under `risc0-groth16-sys`. The worker builds
  unchanged otherwise. The BASELINES cold-start line ("groth16 PSOs bound that time, at ~25 s") should
  be re-measured on the quiet machine after merge.
- The shrink_wrap process-level A/B could not be resolved under this session's GPU contention. The
  in-process A/B settles that the archived PSOs run at the same speed. The quiet baseline should
  include `RISC0_G16_METAL_ARCHIVE=0` as a knob arm.
