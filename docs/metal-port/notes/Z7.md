# Z7: retire the legacy zkp Metal kernels

Branch `metal/Z7` (worktree `/Users/user/zkminer/deps/risc0-wt-Z7`), based on `zkminer/metal` @ `a695b814b`.
Plan: 4.1 row Z7 and the "current Metal-only kernels" row of the kernel table (legacy oracle behind
`RISC0_METAL_LEGACY=1`, deleted in Z7). Builds on Z2 (NTT oracle), Z3 (classic Poseidon2 oracle),
Z4 (`multi_poly_eval` left uncalled), Z6 (suite + budgets).

## What was removed / changed
| File | Change |
|---|---|
| `sys/kernels/zkp/metal/ntt.metal` | **Deleted**: `multi_bit_reverse`, `multi_poly_eval`, `batch_expand`, `multi_ntt_fwd_step`, `multi_ntt_rev_step`. Its one live kernel, `gather_sample` (FRI query gather, plan row "keep"), moved to `misc.metal` unchanged except scalars as `constant uint32_t&` (plan 2.1; the host binds them with set_bytes as before). |
| `sys/kernels/zkp/metal/zk.metal` | **Deleted** (`zk_shift`; replaced by `nttx_zk_shift_batched` since Z2). |
| `sys/kernels/zkp/metal/poseidon2.metal` | **Deleted** (`poseidon2_fold`, `poseidon2_rows`; replaced by pv.metal since Z3). |
| `sys/kernels/zkp/metal/eltwise.metal` | Removed `eltwise_zeroize_fpext` (no caller anywhere: `alloc_extelem_zeroed` uses a blit fill) and the unused `sha256.h` include. `eltwise_mul_factor_fp` stays: its only Hal caller was the legacy iNTT, but F0's `dispatch_groups_bytes_and_loaded_library` plumbing test uses it as the `KernelArg::Bytes` kernel (comment updated). |
| `sys/build.rs` | zkp Metal list without `ntt.metal`, `poseidon2.metal`, `zk.metal`. |
| `zkp/src/hal/metal.rs` | `KERNEL_NAMES` regenerated: one group per .metal file in build.rs order, 9 names removed (`batch_expand`, `eltwise_zeroize_fpext`, `multi_bit_reverse`, `multi_ntt_fwd_step`, `multi_ntt_rev_step`, `multi_poly_eval`, `poseidon2_fold`, `poseidon2_rows`, `zk_shift`), 58 remain. `MetalHashPoseidon2Legacy` / `MetalHalPoseidon2Legacy` removed; the `#[path] mod pv_poseidon2` workaround is now plain `mod poseidon2` (the clashing `core::hash::poseidon2` import was only used by the legacy hash). New `#[cfg(test)] mod tests_z7`. |
| `zkp/src/hal/metal/ntt.rs` | `ntt::legacy` module (old host code + `compute_launch_params`), `NttState::legacy`, `set_ntt_legacy`, `ntt_legacy` and every `if self.ntt_legacy()` branch removed; `has_commit_coeffs_lde` is now just `10..=23`. `RISC0_METAL_LEGACY` is no longer read anywhere. |
| `zkp/src/hal/metal/poseidon2.rs` | `Poseidon2Kernels::Classic`, the classic buffers/branches, and the `RISC0_METAL_LEGACY=1` / `RISC0_METAL_POSEIDON2=classic` selection removed (`classic` now hits the existing "unknown, using default" warning). `pv` / `m32` unchanged. |
| `zkp/src/hal/metal/tests_z2.rs` | Three-way (CPU / Metal / legacy Metal) checks became two-way (CPU / Metal) in every test; same shapes. `ntt_host_logic` loses its legacy assert; the ignored `ntt_timings` times only ntt_x. |
| `zkp/src/hal/metal/tests_z3.rs` | `legacy_oracle_matches_pv` deleted; the `classic` config removed from `fold_tree_configs` and the ignored `bench_fold_tree`; ignored `bench_hal_entry_points` reports pv only. |
| `zkp/src/hal/metal/tests_z7.rs` (new) | `kernel_names_match_metallib`: the metallib's `function_names()` equals `KERNEL_NAMES` exactly (no duplicates, nothing unlisted, nothing missing) and none of the retired names is built. Guards future "regenerate KERNEL_NAMES" drift. |

## Measurements
- zkp metallib (`target/debug/build/risc0-sys-*/out/metal_kernels_zkp.metallib`): **562 766 B before, 511 471 B after** (-51 295 B, -9.1 %). PSOs built per process: 67 -> 58.
- Peak GPU memory: Z7 changes no allocation on the ported paths, so the per-method peaks of Z6's table stand. What disappears: the legacy Poseidon2 hash's round-constant/diagonal buffers (only allocated by the legacy HAL or the classic config) and the 9 PSOs. The 4 GB budget result above (lg 20 x 211 commit needs 3.3 GiB `evaluated` + 1.65 GiB already allocated) is unchanged from Z6.
- No timings taken (nothing on the hot path changed; legacy timings live in Z2/Z3 notes).

## Assumed / gaps
- Correctness of the ported paths now rests on the CPU HAL (DualHal/testutil/two-way tests) and the CPU-verified round-trip seals (Z6); the legacy Metal kernels no longer exist as a second GPU oracle. They agreed bit for bit with the ported paths at every shape up to the Z7 base (Z2/Z3 notes).
- `eltwise_mul_factor_fp` is kept for the F0 plumbing test only (one extra PSO). Removing it means porting that test to another `Bytes` kernel.
- `mix_poly_coeffs` (table-less) is not legacy: Z4's dispatcher still uses it above 2048 inputs.
