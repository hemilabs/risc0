# P31-09: independent recursion ZK noise in every Metal path (security) (2026-11-16)

Branch `metal/P31-09` (worktree `deps/risc0-3.1-wt-P31-09`, from `metal/P31-08` `85d6b85af`).
Plan: `scratch/r31/PORT_PLAN.md` 1.2 row 5, section 5 row P31-09; upstream `f68f86020`. Builds on
P31-01 (the `witgen.rs` merge resolution), C1 (row-pass kernels), C9 (seeded seal check), C11 (row
passes), C14 (staging). Scratch and logs: `scratch/w8/P31-09/` (`logs/`, `ab/`, `ir/`, `stress/`).

## Problem

risc0 3.1 (`f68f86020`) fills the `ZK_CYCLES` noise rows of the recursion data and accum groups with
one independent `BabyBearElem::random` value per cell. 3.0 used `vec![x; n]`: one value repeated over
the whole tail. P31-01 resolved `witgen.rs` the 3.1 way in every mode. Three things remained:

- The Metal HAL still had `fill_tail`, which dispatches `recFillTail` and writes one value into the
  last `zk` rows of every column. No prover path called it after P31-01, but it was still on the HAL.
- `c11_row_passes_match_generic` used it.
- No test showed that the noise rows hold distinct values, with row passes on or off.

## Path audit (where each recursion witgen path gets its noise)

All recursion proofs go through `RecursionProverImpl::prove_shared` (`prove/mod.rs`), which calls
`WitnessGenerator::new` and then `WitnessGenerator::accum`. There is no other producer of `data` or
`accum`. Both tails are written only by those two functions, through `Hal::eltwise_copy_elem_slice`
of an independent-value vector. Nothing else writes rows `>= total - ZK_CYCLES`:

- `Program::new` asserts `code_rows <= 2^po2 - ZK_CYCLES`, so no witgen writes the tail.
- `accum.rs` asserts that the accum kernels leave the noise rows untouched.
- Every zeroize maps only INVALID to 0, and noise is never INVALID.

| path | how it is selected | data noise | accum noise | tail fill? |
|---|---|---|---|---|
| CPU HAL (`CpuCircuitHal`, stock prover, `RISC0_METAL_REC_SEAL_CHECK` reference) | non-metal build / `cpu::recursion_prover` | `draw_noise(seed, 1, ZK_CYCLES*128)` -> `CpuHal::eltwise_copy_elem_slice` | `draw_noise(seed, 2, ZK_CYCLES*12)` -> same | no |
| Metal default (generic passes) | `RISC0_METAL_REC_ROW_PASSES` unset | same draw -> Metal `small_eltwise_copy_elem_slice` (upload + `eltwise_copy_fp_region`) | same | no |
| Metal row passes (C11) | `RISC0_METAL_REC_ROW_PASSES=1` | `recInitRows` (zero past live), then the **same** copy, then `recZeroizeRows` over the live rows only | same as default (the accum has no row passes) | **no** (P31-01 removed the call; P31-09 removed the Metal impl) |
| C11 host chains / captures replay (`prepare()`, `replay_preflight`) | default on Metal | inputs only (chain rows uploaded into live rows); noise as above | as above | no |
| C14 staging (`RISC0_METAL_REC_STAGE=1`) | opt-in | stages trace inputs (wom/cycles/iops/chains) in shared buffers; noise as above | as above | no |
| host-generated witness (`upload_host_witness`, errata 8.4; Intel prewitgen) | Intel only (`cfg(feature = "intel")`) | upload overwrites the whole buffer, **then** the same noise copy | as above | no (row passes are off with a host witness) |
| `RISC0_HIP_REC_ZCHECK` / host-chain check / prewitgen check / `RISC0_METAL_REC_WITGEN_CHECK` | validation | compare witnesses before the noise; noise as above | as above | no |
| Seq modes (`StepMode::SeqForward/Reverse`) | CPU fallback inside the Metal HAL | through `WitnessGenerator`, as above | as above | no |

The RNG is `rand::rng()`, the stock prover's, with `n` draws in order and the stock copy layout
(`noise[col * ZK_CYCLES + r]` -> row `total - ZK_CYCLES + r`). Under `with_noise_seed(s)` the RNG is
the existing seeded `StdRng` per stream (`s ^ stream * 0x9e3779b97f4a7c15`, stream 1 data, 2 accum).

`grep` for `fill_tail` / `recFillTail` (`logs/grep_fill_tail.txt`) finds:

- the trait method (`hal/mod.rs`, `allow(dead_code)` as on R31);
- the HIP HAL impl (not owned; the witgen never calls it);
- the Metal doc comment;
- a negative assertion in `c11_row_passes_match_generic`;
- the kernel and its C1 tests / name lists in recursion-sys.

**No noise path calls either.**

## Changes (commit `recursion: independent ZK noise in every Metal path; drop the Metal tail fill`)

1. **Metal `fill_tail` removed** (`hal/metal/witgen.rs`). The Metal HAL now keeps the trait default,
   which fails (`c11_row_passes_match_generic` asserts that it fails). The trait method stays as R31
   has it (`allow(dead_code)`, implemented by the HIP HAL). Its doc now says it is not for noise.
   **`recFillTail` is kept** as the C1 port of `ffi.cu`'s kernel, with a comment that no prover path
   dispatches it. Deleting it would mean editing files outside this item:
   - `recursion-sys/src/lib.rs` (the metallib kernel-name list);
   - `tests/c1_metal_kernels.rs` (its CPU-reference check);
   - `tests/c4_metallib_smoke.rs`.

   With no Rust caller, it is unreachable from the prover. The init/zeroize row passes are unchanged.
2. **One draw function** (`witgen.rs` `draw_noise(seed, stream, n)`) for both tails. It is
   monomorphic over `rand::rng()` or the seeded `StdRng`, instead of `Box<dyn RngCore>`. The values
   are identical; the test below pins the seeded stream.
3. **Noise drawn ahead** (`EarlyNoise`). Both tails' values (131072 + 12288 draws, about 3.4 ms of
   CPU) are drawn on a helper thread started at the top of `WitnessGenerator::new`. The Metal witgen
   ends in a wait, so before this change the GPU sat idle during the draw. The values are joined and
   copied at the same two points as before. The seed is read on the proving thread and passed in, so
   `with_noise_seed` gives the same values as an in-place draw. `RISC0_RECURSION_NOISE_OVERLAP=0`
   draws in place, like stock. That knob only moves where the draw runs. **No knob brings back
   repeated noise.**

## Profile before

- Micro-benchmark of the draws (host only, 7 reps): 3.34-3.41 ms per proof with `Box<dyn RngCore>`
  (data 128 cols, accum 12 cols, x 1024 rows). Monomorphic `rand::rng()`: 3.02-3.07 ms.
  `BabyBearElem::random` does 6 `u64 % P` per element, about 23 ns per element.
- This matches P31-08's +3.35 ms `pre_accum` delta (3.0 -> 3.1). The Metal witgen
  (`check_fault`) waits on the GPU, so this time was serial with an idle GPU.

- **Overlap: -3.1 to -3.3 ms per lift (-3.0 %), -2.85 ms per join**, with row passes on and off and
  at every budget. That is far outside the A-vs-A spread, so it is kept as the default.
- In-place draw (B0) vs A: -0.1 to -0.3 ms. This is the monomorphic RNG, about the A-vs-A size, so
  it is "no change".
- The independent draw therefore costs ~3.4 ms of CPU per proof (the 3.0 -> 3.1 delta P31-08
  measured). It is now hidden behind the witgen, and lift time is back to within ~0.3 ms of 3.0
  (P31-08's 3.0 replay: 102.8-107.8 ms per lift).
- Row passes on vs off: still no difference beyond noise (about 0.3 ms in A), as C11 found.

**Memory:** the GPU allocations and dispatches are unchanged. The host holds 0.56 MiB of noise for one
proof, plus one short-lived thread per proof. Peak memory is unchanged at both simulated budgets (same
buffers; the 4/8 GiB runs above passed with the same timings).

## Knobs

- `RISC0_RECURSION_NOISE_OVERLAP=0`: draw the noise in place on the proving thread (stock placement)
  instead of on a helper thread during the witgen. The values are independent per cell either way.
  Test hook: `witgen::with_noise_overlap`.
- No knob restores repeated noise.
