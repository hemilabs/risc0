## 2. Sizes, budgets, `MemOptions::split_h`

### `split_h` (kept; default `auto`, engaged only when needed)

The MSM scratch is sized for `cap = max(witness length, n)` scalars because MSM H runs over the whole domain
(n = 2^23); its `sorted` buffer alone is nwins * cap * 4 = 512 MiB. With `split_h`, MSM H runs as two MSMs over
the domain's halves (sum of the two window-sum sets on the host: the same group element), so cap =
max(6,257,165, 2^22) and the scratch shrinks by 130 MiB (planned 4169.0 -> 4038.9 MiB, allocated 4142.1 ->
4012.1 MiB). c still fits in `sorted` during the NTT (382 MiB >= 256 MiB).

Encoding detail (the first attempt was wrong, caught by the bit-exact test: H differed): MSM H's pieces are
written into the lent a, b buffer, where the second half of h still is. So, in split mode:
- one blit copies h's second half to the second half of b (`copy_h2`, 0.7 ms);
- the first half's dense transposed scalars use b's first half (G15 `htr`);
- the H MSMs run without G12 `lent_groups`, so their pieces stay inside a (`layout` checks that the piece
  buffer is at most n Fr, else the split layout is not offered);
- `lent_groups` is restored for the witness MSMs (B2 stays one group).

Speed (`g10_bench`, real v0.2.0 witness, in process, variants off / on / off, 9 interleaved reps):
- unprofiled: GPU 607.8 [605.1..614.0] / **607.6** [605.7..614.7] / 609.9 [605.8..617.8] ms: no change against
  the A-vs-A spread (2.1 ms).
- profiled (`G10_PROFILE=1`): MSM H 174.2 -> 88.0 + 88.0 ms, sort_h 12.4 -> 6.3 + 6.3 ms, copy 0.7 ms: **+2.5 ms**
  per proof (+0.4 %).

Because of that small cost, the default is `auto`: split only when the unsplit footprint does not fit the
working-set room (explicit budget, else the device's recommended working set, minus what is allocated) and the
split one is smaller. At the default and 8 GiB budgets nothing changes (same layout as before this item); at
4 GiB it is what makes the wrap possible. Knobs: `RISC0_G16_METAL_SPLIT_H=on|auto|off`,
`RISC0_G16_METAL_G10_OFF=split_h` (= off), `RISC0_G16_METAL_G10=0` (G9 layout, off). `MemOptions::parse` takes
`split_h=on|auto|off`. `BuildStats::split_h` and `MetalProver::split_h()` report the decision.

Smallest budget: planned 4038.9 MiB + ~4 MiB already allocated. Measured (`logs/minbud_*.log`): 4035 MiB is
refused with the clean budget error, and 4045 MiB builds the split prover (4012.1 MiB). So ~3.95 GiB (wave 7:
~3.84 GiB). Margin at 4 GiB: 4096 - 4043 = 53 MiB of planned room.

Layouts on the v0.2.0 key (`logs/final_g10_split.log`, planned / allocated MiB): G9 layout (`base`)
6031.9 / 6004.1; `base,+compact` 4856.0; `base,+alias` 5344.9; G10 all 4169.0 / 4142.1; all + split
4038.9 / 4012.1. Every layout gives the same proof (`g10_mem_options_bit_exact`).
