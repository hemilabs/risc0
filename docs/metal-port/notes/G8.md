## The P0 fix (M1 "G8" issue)

- `metal::prestart` no longer loads the key: it checks the component and preloads the witness
  graph (CPU) in the background.
- `gpu_prove`: witness on a helper thread; the calling thread runs `pre_gpu`, **then** loads the
  key (if not cached), still overlapped with the witness; then joins, takes `exclusive()`, proves.
  No retry is needed since the load can no longer race the release. Explicit `preload_srs` is
  unchanged (documented "after STARK proving is complete").
- Cost: the key load (1.0-2.3 s measured here, loaded machine) now starts after `pre_gpu` (0.1-0.5 s)
  instead of at identity_p254 time; it overlaps the witness (0.9-12 s under load). On machines that
  keep the key cached (M1 keeps it at >= ~36 GiB limits) nothing changes.

## zkvm export (M1 open issue)

`risc0_zkvm::release_hal_buffers()` (re-exported only with `feature = "metal"`; the function in
`host::server::prove` became `pub` inside its crate-private module, so other builds' public API is
unchanged). It drops the **calling thread's** cached segment and recursion provers (their HAL pools)
and is a no-op for a prover in use. Exercised by `tests_metal_wrap` (after the wrap: 21.7 MiB held).
