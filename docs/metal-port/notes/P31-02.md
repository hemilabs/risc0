This is the first link of the rv32im chain (P31-02 -> P31-04 -> P31-03 -> P31-05 -> P31-06). It

## Changes

1. `python3 kernels/cuda/cuda2metal.py incs -o kernels/metal` (in rv32im-sys) regenerated the three
   checked-in includes from the 3.1 zirgen output:

   | file | translator counts | diff vs the 3.0 file |
   |---|---|---|
   | `defs.metal.inc` | `array=0, qual.ns_constexpr=6` | one line: `kRegCountGlobal` 90 -> 91 (3.1's `totalCycles` global). The other register counts are unchanged (accum 103, code 1, data 211, mix 36, test 211) |
   | `types.metal.inc` | `array=100` (3.0: 99) | 3377 -> 3421 lines, 444 structs on both sides. The `argU16` array grows from 4 to 10 entries (`ArgU16Layout4LayoutArray` -> `ArgU16Layout10LayoutArray`), and the `_extraN` members of the affected structs change from `ArgU8Layout` to `ArgU16Layout` (10-15, then U8 16-19). This is the new constraint shape of 3.1's circuit fix |
   | `layout.metal.inc` | `array=0, qual.device_data=1203` (3.0: 1194 `constant` tables) | 7076 -> 8414 lines: the layout tables for the new types and their shifted offsets |

   All three files are **byte-identical** to the plan's scratch preview
   (`scratch/r31/gen/incs/{defs,types,layout}.metal.inc`), so there is no difference to explain.
2. `rv32im-sys/build.rs`:
   - `METAL_INCS_CHECK_TU`: `kRegCountGlobal == 90` -> `== 91`. The other asserts are unchanged and
     still hold on 3.1: `kLayout_TopAccum.columns[0].col == 23` (kUserAccumSplit), accum 103,
     code 1, data 211, mix 36.
   - `R12_EF_TABLES_STUB` (the `ef_tables.rs` written under `RISC0_SKIP_BUILD_KERNELS`):
     `EF_NPC` 458 -> 484, `RK_QN` 107 -> 109, `RK_HN` 62 -> 49. Source: the `ef_tables.rs` that the 3.1
     chain emits (`regen.py --metal`, scratch copy `scratch/r31/gen/ef/ef_tables.rs`, lines 10/12/14),
     not the brief. `EF_NPM` is still derived (`EF_NPC + RK_QN + RK_HN` = 642, 3.0: 627).

Nothing else was touched. The evalfast (`to_metal.py`, `eval_check.rs`) and R6 eval translator pins
belong to P31-03 and P31-04.
