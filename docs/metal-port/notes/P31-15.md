## 4. identity_p254 seal fixture against the stock 3.1 verifier

P31-12's `groth16/tests/data/identity_p254_seal.{bin,json}` (sha256 `49c1aa36...4e9b` / `6df0a44d...6299`).
`scratch/w8/P31-15/stockverify/` is a separate crate on **crates.io** `risc0-zkvm =3.1.0`,
`risc0-circuit-recursion =4.1.0`, `risc0-zkp =3.0.6` (no path deps, no patches; `cargo tree` shows no local
package other than itself). It rebuilds the identity_p254 `SuccinctReceipt` (serde, since the type is
`non_exhaustive`): the seal, `hashfn = poseidon_254`, `control_id` = the json's `bn254_control_id`, a one-leaf
inclusion proof (root = leaf, as `identity_p254` builds it with `with_control_ids([BN254_IDENTITY_CONTROL_ID])`),
the claim pruned to `claim_digest`, and verifier parameters with `control_root = bn254_control_id`,
`inner_control_root = control_root`. Then the stock `verify_integrity_with_context`.

- 3.1 fixture: `fixture ids == stock 3.1 Groth16ReceiptVerifierParameters::default(): true` (control root
  `e6feef13...551d`, BN254 identity id `de81d091...c20a`; the worktree's `circuit/recursion/src/control_id.rs` is
  byte-identical to crates.io 4.1.0's) and **`STOCK 3.1 VERIFY: OK (55667 seal words)`** (`logs/stockverify_r31.log`).
- 3.0 fixture (frozen tree's copy): ids differ (`a54dc85a...`, `c07a6514...`) and the seal is **rejected**
  (`control_id mismatch: 67e66411...`, `logs/stockverify_30_neg.log`).
- Tamper checks (`logs/stockverify_tamper.log`): one flipped seal bit -> `verification indicates proof is invalid`;
  one changed claim-digest nibble -> `journal digest mismatch`.

Two build details of the stock crate: the stock `VerifierContext::default()` has no `poseidon_254` suite, and the
stock `risc0-zkp` builds that suite only with its `prove` feature, so the crate enables `prove` and inserts the
stock `Poseidon254HashSuite` (CPU code). `prove` pulls stock `risc0-sys`, whose own (unpatched upstream) Metal
kernels do not compile with this Metal toolchain (`poseidon2.metal:89: use of overloaded operator '=' is
ambiguous`), so that scratch build sets `RISC0_SKIP_BUILD_KERNELS=1`: the verifier never touches a GPU kernel. No
risc0 tree build here sets it (nor `RISC0_SKIP_BUILD`).
