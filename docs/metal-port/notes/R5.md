## Measurements: peak GPU memory
No HAL phase runs these kernels yet (R8 wires witgen), so there is no per-phase peak from the
prover. Kernel-only footprint per segment (from the bindings): data + pre_data = 2 × rows × 211 ×
4 B (po2 20: 1.65 GB; po2 18 on the 16 GB minimum tier: 0.41 GB), global 360 B, tables 263 KB,
preflight cycles 36 B/row + txns 20 B each + bigint bytes. The separate pre_data copy doubles the
data footprint; single-buffer mode (bind data twice) removes it once R15 proves it bit-exact.

## Assumed / not verified
- **No bit-exactness check against the CPU yet**: correctness of the translated graph and the
  extern port rests on R2's verified passes, compile success, and the by-construction port. R8's
  `witgen_matches_cpu` is the runtime gate.
- `extern_getDiffCount` is not clamped: R1's `PreflightTrace` has no cycle count; its argument is
  `2 * cycle (+1)` of a witness value.
- noinline honoured by the back end: the 7x PSO time difference vs the inlined build suggests so,
  not otherwise inspected.

## Issues for later items
- **R8**: bind per the table above; `WitgenParams` is 48 B (mirror `#[repr(C)]` and assert); zero
  tableU8/tableU16 and the fault word before the first launch; bind a dummy buffer for empty
  txns/bigint and for `perm` when `usePerm = 0`; memcpy preflight cycles (txnIdx is mutated);
  host must assert `rows * 211 < 2^32`; par launches = [0, split) and [split, lastCycle) as CUDA;
  seq modes = one 1x1 dispatch per 4096 positions with `SeqParams{begin,end,split,lastCycle}`.
  Fault bits: 0x1/0x2 lookup, 0x4 txn, 0x8 bigint, 0x10 assert (41 unreachable-mux-arm sites),
  0x20 cycle index. The R7 HAL now builds these three PSOs at first load: ≈ 6.5 s cold.
