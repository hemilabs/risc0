# Z2: NTT (ntt_x port)

Branch `metal/Z2`. Plan rows followed: 4.1 row Z2 and the `_CT_X/_GS_X`, `batch_bit_reverse`,
`batch_lde_expand`, `nttx_fill_one/gather_pow`, `nttq` and legacy rows of the kernel table;
errata 8.3 (`bit_rev_permutation` -> naive Metal bit reversal for n < 4096, `sppark_init` ->
CPU-built tables, nttq not ported) and 8.4 (`batch_interpolate_ntt_zk_shift_from` is Z2).

## What was ported, from where
Kernels (`ntt_x.metal`), from `sys/kernels/zkp/cuda/supra/ntt_x.cuh` and sppark 5f68eb3:
- `ct_x<Z, COALESCED>` = `_CT_X` (ntt_x.cuh:26-218), `gs_x<Z, COALESCED>` = `_GS_X`
  (ntt_x.cuh:221-406), statement for statement: expand-on-load (`lg_expand`, zero synthesis) and
  `skip_expand` (replicate, skip the trivial levels) in CT stage 0; the zk-shift post-multiply
  `lo[k & 1023] * hi[k >> 10]`, `k = bitrev(i, lg)` in the last GS pass; `n^-1` scaling in the
  last GS pass (`is_intt && stage == iterations`; CT keeps its never-taken intt branch); the V3
  barrier fix before the coalesced transpose. `[[host_name]]` instantiations `ct_x_1`, `ct_x_8`,
  `ct_x_8_coalesced`, `gs_x_1`, `gs_x_8`, `gs_x_8_coalesced` (X_launcher's `<1>`,
  `<Z_COUNT=8>`, `<8, true>`), `[[max_total_threads_per_threadgroup(512)]]` before the template
  (the attribute is rejected on explicit instantiations: "not allowed on explicit instantiation
  declarations"; the template's attribute carries over, PSO max = 512 verified by
  `ntt_host_logic`).
- **Divergence from supra (fix round 1):** supra `ntt_x.cuh:123-124` guards the first
  radix-2 butterfly with `if (s0 == 1)` where `s0 = skip ? lg_expand : 1`. With `skip_expand` and
  `lg_expand == 1` that butterfly re-runs the level already folded into the replicated load and
  yields `(2c, 0)` instead of `(c, c)`. The CUDA/HIP code only reaches skip with `lg_blowup = 2`, so
  the bug is latent there; the Metal Hal accepts any expand ratio, so `ct_x` here tests `!skip`
  instead. Found by the adversarial review (expand by 1 at output lg 2..23 was wrong; expand by
  0/2/3/5/6/7 was right). Covered now by `ntt_expand_ratios_lg_1_20`.
- sppark helpers: `get_intermediate_roots` (kernels.cu:297), `coalesced_load/store`, `transpose`
  (kernels.cu:320-358), `bit_rev` (parameters.cuh), `shfl_bfly` -> `simd_shuffle_xor` on the raw
  word, `csel` -> `?:`, `__syncwarp` -> `simdgroup_barrier(mem_threadgroup)`,
  `__syncthreads` -> `threadgroup_barrier(mem_threadgroup)`. The shared exchange is one dynamic
  `threadgroup uint*` (raw Montgomery words) used both as `xchg[blockDim][Z]` and by transpose.
- `bit_rev_z_batched_64` = `bit_rev_z_batched<64>` (ntt_x.cuh:514-560) in place, body once (the
  CUDA do/while runs once for Z_COUNT > warpSize), on raw `uint` words.
- `bit_rev_permutation_batched` = sppark `bit_rev_permutation` (kernels.cu:18), swap form, as one
  2-D dispatch over (n, cols) instead of CUDA's per-column launches (deviation, same result).
- `nttx_zk_shift_batched` (ntt_x.cuh:673) as a 2-D (n, cols) dispatch.
- `bit_rev(i, 0)` returns 0 explicitly (MSL shift by 32 is undefined; PTX clamps to 0).
- Not ported: the `nat` output of `_GS_X` (no host path uses it), `bit_rev_t2_*` (HIP),
  nttq (> 32 KB threadgroup), `nttx_fill_one/gather_pow` (tables on the CPU),
  `batch_lde_expand_kernel` (expand-on-load replaces it).

Host logic (`ntt.rs`), 1:1 from ntt_x.cuh / ntt.cu:
- `NttTables`: sppark `NTTParameters` for both directions built on the CPU by the formulas of
  `generate_partial_twiddles` / `generate_all_twiddles` / `generate_plus_one_twiddles`
  (parameters.cuh:87/108/181) from sppark's own Montgomery constants
  (`parameters/baby_bear.h`, non-canonical: group_gen 3, `forward/inverse_roots_of_unity`,
  `domain_size_inverse`), embedded in ntt.rs. At build time every sppark root and
  `domain_size_inverse` is asserted equal to risc0's `ROU_FWD/ROU_REV[k]` and `2^-k`. Layout per
  direction: partial `[5][64]`, the radix-11..6 blob (sppark `twiddles[5]` first), plus-one
  `[12][1024]`; one buffer per direction per HAL, bound with offsets.
- zk tables (`nttx_tables`, ntt_x.cuh:682): `lo[t] = 3^t` (1 beyond n), `hi[u] = 3^(1024u)`, built on
  the CPU per lg and cached per HAL (same field elements as sppark's `LDE_powers`-derived ones).
- `ct_steps`/`gs_steps` (449/464; the gfx12 split is HIP-only, not ported), `x_step` =
  `X_launcher::step` (410: radix, block `min(2^(lg-1), 2^(radix-1))`, grid `(nblocks[/8], cols)`,
  threadgroup bytes `[8*]4<<(radix-1)` <= 16 KB, variant selection), `ct_x` (471, incl. the
  `skip_expand` condition), `gs_x` (494), `bitrev_batched` (641), `nttx_batch_zk_shift` (705),
  `nttx_auto_chunk` (713), `nttx_commit` (725, without its nttq branch; column chunks are bound
  by buffer offset).
- Entry points: `batch_expand_into_evaluate_ntt` = HIP `hip_expand_ntt`'s non-nttq branch
  (ntt.cu:449: `ct_x(..., lg_expand, skip=true)`; CUDA itself uses sppark NTT::Base/nttq there);
  `batch_interpolate_ntt` = `sppark_batch_iNTT` (one batched GS run instead of per-column
  `Base_dev_ptr`); `batch_interpolate_ntt_zk_shift` = `sppark_batch_iNTT_zk_shift_fused` with the
  zk shift fused in the last GS pass; `batch_interpolate_ntt_zk_shift_from` = the same with the
  first pass reading `src` (out of place); `zk_shift` = `nttx_batch_zk_shift`; `batch_bit_reverse`
  = `sppark_batch_bit_reverse_tiled`; `commit_coeffs_lde` = `sppark_commit_coeffs_lde` with
  `has_commit_coeffs_lde = 10..=23`. Each ends with `flush()` (CUDA `gpu.sync()` points).
  `lg == 0`: copy / no-op (CUDA returns early).
- Init cross-check: the first table use in a process runs GPU expand+CT (lg 3, 12, 19: one, two
  and three passes, `_1`/`_8`/`_8_coalesced`) and GS + zk post-multiply against `core::ntt`
  (`expand`+`evaluate_ntt`, `interpolate_ntt` + `3^bitrev`) and panics on any difference.
- `RISC0_METAL_LEGACY=1` (read in `MetalHal::new`; `MetalHal::set_ntt_legacy` for tests): the old
  `multi_ntt_*`/`batch_expand`/`multi_bit_reverse`/`zk_shift` kernels; the fused methods then use
  the unfused compositions and `has_commit_coeffs_lde` is false.
- Unused validation bindings avoided: index 3 (plus-one) is unbound for the `_1` variants and
  lo/hi for `gs_x_8_coalesced`; the plain GS variants get the twiddle table as a never-read dummy
  lo/hi when they do not post-multiply (they reference it behind the runtime flag).

## Assumed / not verified / gaps
- Bit-exactness against sppark's *GPU-generated* tables is by construction (same formulas, same
  constants, field arithmetic is exact) plus the CPU-reference cross-checks; no CUDA machine was
  available to diff the table buffers word for word.
- The `RISC0_METAL_LEGACY=1` env path is read in `MetalHal::new`; tests switch through
  `set_ntt_legacy` (setting env vars in parallel tests is racy). Fix round 1 ran the whole
  `hal::metal` suite once with the variable set (49 passed).
- Row size 1 (lg 0): Metal bit_reverse / zk_shift / interpolate_zk_shift_from accept it (no-op or
  copy) while the CPU HAL panics; the CPU is undefined there, not treated as a mismatch.
- The coalesced transpose relies on 8-lane groups staying inside one simdgroup (no barrier between
  the load transpose and the store transpose when iterations <= 6), as CUDA relies on warp
  synchrony; true on Apple GPUs, flagged for Z8's audit.
- The init self-check flag is set before the check finishes, so a second HAL on another thread
  may run NTTs before it completes (the tables are deterministic; reporting order only).
- po2 22 x 211 (and lg 21/22 per-method timings x 211 columns, plan 6.4) not run: ~14 GB evaluated
  buffer per HAL is too much next to other agents' jobs. The 22 shapes run are single/two-column.
- The tests are memory-heavy (CPU + Metal + legacy copies of lg 20 x 211 inputs); run the Z2 module
  with `--test-threads` limited if the machine is shared.
- `redundant setting` validation warnings from the runtime's threadgroup-length re-binding (above).
- The self-check runs on the first NTT of the process and syncs once (a few ms incl. a 2^19
  CPU NTT).
